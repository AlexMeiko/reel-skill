**一句话**：一行 120px 的中文大字间歇性「故障」——红/青通道分离、横向切片错位、整幅抖动、
信号丢失——发作之间是**干净到像素的静止态**，而每一次发作的时机、幅度、切片位移
**全部是 `t` 的确定性函数**，没有一次随机数、没有一个定时器。

## 1. 常见写法为什么在本 skill 里会坏

| 常见写法 | 坏在哪 | 本 skill 的 seekable 改法 |
|---|---|---|
| `Math.random()` 每帧重掷切片偏移 | 画面不可复现，seek 到同一 `t` 得到不同帧（反例 A2：同 t 两次截帧 0/5 一致） | `hash(i)` 确定性伪随机 + 时间量子 `q = ⌊t×24⌋`。同一 `q` 永远同一组偏移 |
| `setInterval` 按节拍触发发作 | 位置取决于「页面活了多久」，seek 回不到那一刻（反例 A3：1/5 一致） | 节拍表写成**字面量数组** `BEATS`，`amp = Σ pulse(t, beat)`，纯 `t` 的函数 |
| 发作强度用「上一帧 + 衰减」累加 | 跨帧状态；只给 `t` 算不出这一帧 | 闭式包络 `pulse()`：瞬时起振 → 平台 → 二次衰减，只吃 `t` |
| CSS `infinite` 循环播放故障 | **它其实可 seek**（`getAnimations()` 会被 pause+设 currentTime，反例 A4 同 t 5/5 一致），坏的是末帧闪回第 0 帧 | 不用 CSS 动画，全部走 `reelDraw(t)`；末帧天然是结束态 |
| `transition` 做切片位移 | 墙钟补间，seek 不等它跑完，画面滞后于 `t`（反例 A5：2/5 一致） | 删掉，位移在 `reelDraw` 里一次算好写一次 |
| 每帧用 canvas 半透明黑覆盖做拖尾 | 依赖上一帧，seek 必坏 | 本特效不需要拖尾；若要，用解析式（按 `t`、`t-dt`… 重画） |
| 数字/游标一套 CSS 一套 JS | 两条时间线，seek 后对不上 | 见 §2.5「单源同步」 |

另外三条本特效特有的坏写法：

- **发作期写成三角尖**：`w` 只是数学窗口，可见时长只有它 1/3，播放时一闪而过，
  15 格 contact sheet 里一格都抓不到。改成**平台型包络**（见 §2.1）。
- **切片组全程挂载**：相邻 `clip-path` 在整数边界上仍可能露 1px 缝，干净帧会出现横向接缝。
  改成「干净壳 / 切片组」**独占切换**（见 §2.4）。
- **每帧改字的 DOM 文本**：会踩到 Chromium 字形缓存栅格化的 1/255 抖动，
  同一 `t` 两次截帧不再逐字节一致（见 §5 踩坑第 1 条，这条是实测踩出来的）。

## 2. 关键技术点

### 2.1 节拍表 + 平台型包络 —— 「不均匀但有节奏」怎么造

```js
/* 字面量节拍表：间隔 0.80 / 0.60 / (0.12) / 0.78 / 0.63 / 0.67 —— 刻意不等距。
   2.02 与 2.14 是一对密集双发；4.22 是收尾大发作。 */
var BEATS = [
  { t: 0.62, w: 0.30, a: 0.45 }, { t: 1.42, w: 0.34, a: 0.62 },
  { t: 2.02, w: 0.22, a: 0.78 }, { t: 2.14, w: 0.30, a: 0.92 },
  { t: 2.92, w: 0.28, a: 0.55 }, { t: 3.55, w: 0.30, a: 0.68 },
  { t: 4.22, w: 0.46, a: 1.00 }
];
function pulse(t, b) {                    // 瞬时起振 → 平台 → 二次衰减
  var d = t - b.t;
  if (d < 0 || d > b.w) return 0;
  var atk = 0.02, hold = b.w * 0.5;       // 0.02s ≈ 一帧内到位
  if (d <= atk) return b.a * (d / atk);
  if (d <= hold) return b.a;              // w 的一半是满幅平台 —— w 就是可见时长
  var u = (d - hold) / (b.w - hold);
  return b.a * (1 - u) * (1 - u);
}
function envAt(t) { var s = 0; for (var i = 0; i < BEATS.length; i++) s += pulse(t, BEATS[i]);
                    return Math.min(1.15, s); }
```

「不均匀」来自节拍表里的**不等距间隔**（0.80 / 0.60 / 0.12 / 0.78 / 0.63 / 0.67），
「有节奏」来自**固定的一套幅度档**（0.45 → 0.62 → 0.78/0.92 → 0.55 → 0.68 → 1.00）。
两者都是字面量，所以节奏可以逐条手调，而不是「调一个随机种子碰运气」。

**为什么用平台而不是三角尖**：三角/二次尖峰的可见时长只有 `w` 的三分之一。
`w=0.30` 的尖峰在 30fps 下只有约 3 帧有振幅，播放时像掉帧；改成平台后
「起振 → 满幅 0.15s → 衰减」，`w` 就是肉眼能数出来的发作长度。
这个改动直接把 contact sheet 上的可见发作从 1 格提到 6 格（§5 踩坑第 4 条）。

### 2.2 时间量子 + 闸门 —— 「随机感」怎么造

```js
var q = Math.floor(t * QHZ);          // QHZ = 24，每秒换 24 次
var A = envAt(t) * (hash(q * 8.3 + 2.7) > 0.42 ? 1 : 0.34);   // 闸门
```

`q` 把连续时间切成 1/24s 的格子。**同一格内 `t` 不同、`q` 相同，画面完全相同** ——
这正是 seek 稳定的来源：截帧落在 `t=1.0000` 还是 `1.0011`，只要在同一格就是同一帧。

**为什么不取 30/60Hz**：与帧率同频会退化成逐帧噪声，人眼数不出「咔咔咔」的节拍。
24Hz 每格跨 1.25 帧（30fps），有轻微拍频，换字感最明显。

**闸门**是把连续包络切成通断：包络负责「这半秒在发作」，闸门负责「这半秒里抖几下」。
真实的故障不是一条平滑的钟形，而是一串断续的爆音；加闸门之后观感从「渐强渐弱的波」
变成「突突突的信号中断」，同时它仍然只依赖 `q`，照样是 `t` 的纯函数。

`hash` 是多通道的，换常数就是换一条独立随机通道：

```js
function hash(i) { var x = Math.sin(i * 127.1 + 311.7) * 43758.5453123; return x - Math.floor(x); }
var dxR = A * (hash(q * 1.7)        - 0.5) * 26;   // 红层横向分离
var dxC = A * (hash(q * 2.9 + 1.3)  - 0.5) * 26;   // 青层横向分离（独立通道）
var dyR = A * (hash(q * 3.7 + 5.1)  - 0.5) * 5;    // 红层纵向
var sy  = A * (hash(k * 3.1 + q * 0.7 + 4.4) - 0.5) * 6.4;  // 第 k 条切片的纵向撕开
```

### 2.3 `mix-blend-mode: screen` 做通道分离的原理

三层同一份文字绝对定位叠放，**DOM 顺序 = 绘制顺序**：

```
.gl-r  红 #ff2f4f   mix-blend-mode: screen     ← 最先画
.gl-c  青 #00dfe8   mix-blend-mode: screen     ← 叠在红上
.gl-w  白 #f4f8fc   （无 blend）                ← 最后画，压在最上面
```

`screen` 的定义是 `1-(1-a)(1-b)`，对暗背景约等于「加法」。
红与青重叠处 `screen(#ff2f4f, #00dfe8) ≈ (255,234,255)`，接近白 ——
所以两层错开后，**白字边缘外侧会分别露出红边和青边**，这正是色差（chromatic aberration）。

**顺序是关键**：白色层必须最后画且不参与 blend。如果白色在下面，
`screen(白, 任何色) = 白`，红青会被完全吃掉，看不到任何分离。
白层在上、红青在下，白层把重叠区盖住，只在**错位露出来的部分**显示红/青 ——
这就是「白芯 + 红青边」而不是「红青糊成一片」。

### 2.4 克隆切片 + 独占切换

```js
/* 6 条切片，每条都是同一份三层文字的全幅副本，靠 clip-path 取一条横带 */
s.el.style.clipPath = "inset(" + b[0] + "px 0 " + (STAGE_H - b[1]) + "px 0)";
s.el.style.transform = "translate(" + sx + "px," + sy + "px)";         // 这一条整带错位
s.r.style.transform  = "translate(" + dxR * mR + "px," + ... + "px)";  // 带内红层再分离
```

`clip-path` 作用在**变换之前**的元素自身坐标系里，变换再搬走裁好的结果 ——
所以某条带被搬走后，它原来的位置就空出来露出背景，这就是「撕裂」的观感。

干净帧的接缝问题用**独占开关**解决：第 0 条切片不裁切、专门负责干净壳；
一旦 `ENV > 0.02`，第 0 条 `opacity: 0`、其余 6 条同时上场。
切换发生在包络已经足够大的那一帧（起振只要 0.02s，最小幅度档 `a=0.45`），
所以看不到「干净壳 ↔ 切片组」的切换缝。

### 2.5 单源同步 —— 只有一个真值来源

```js
var q = Math.floor(t * QHZ);
var ENV = envAt(t);
var A = ENV * gateAt(q);
/* 下面所有派生量都从同一次 ENV / A / q 里算出来，各写一次 */
worldEl.style.transform = A > 0.001 ? "translate(...)" : "none";   // 整幅抖动
scanEl.style.opacity    = 0.04 + A * 0.22;                          // 扫描线强度
flashEl.style.opacity   = big * 0.09;                               // 信号尖峰
phEl.style.left         = 1128 * t / D;                             // 游标位置
phEl.style.background   = ENV >= 0.5 ? "#ff2f4f" : "#00dfe8";       // 游标颜色
setReadout("T+" + t.toFixed(2), "发作 " + beatIdx + " / " + BEATS.length);
setStatus(ENV >= 0.5 ? "SIGNAL LOST" : "SIGNAL OK", ...);
```

游标位置、游标颜色、扫描线强度、状态字、两个读数，**全部从同一次 `ENV/A/q` 派生**，
不存在「CSS 动一条 + JS 动另一条」。发条尺上的 7 个刻度位置也是直接从 `BEATS` 数组算的
（`1128 * BEATS[i].t / D`），一个字节都不另算。

> 注：`phEl` 的颜色看 `ENV` 而不是闸门后的 `A`。若看 `A`，游标会在 24Hz 上疯狂闪红/青，
> 那是噪声不是信息。扫描线才跟着 `A` 抖 —— 因为它本来就是「信号强度」本身。

### 2.6 发条尺：把节拍表画出来

底部 1128px 的尺代表 0→5s，7 个刻度就在 `BEATS[i].t` 的位置。
刻度三态：未到（暗）→ 已过（亮）→ 正在发作（红、加高）。
2.02 与 2.14 这对双发在尺上是**紧挨着的两根红刻度**，观众一眼能看出「刚才那是两下」。
这把「不均匀的节奏」从「感觉」变成了「读得出来的量」，也是本特效唯一的信息型装饰。

### variant-a 的 SMIL 实测结论：**可 seek，且逐字节确定**

这是本特效要求单独回答的问题。`runtime/seek.js` 对每个 `<svg>` 调
`pauseAnimations()` + `setCurrentTime(t)`。为了排除「画面里还有别的随时间变化量」的干扰，
我写了一个**最小实证页** `evidence/smil-seek-test.html`：它**故意不定义 `reelDraw`**，
页面里唯一的随时间变化量就是一条 SMIL 时间轴（`feDisplacementMap/@scale`，
keyTimes `0;0.30;0.31;0.70;0.71;1`，values `0;0;60;60;0;0`）。

```
# evidence 页已不在库里；对比请把 qa-dir 写到 $PWD/reel-out/
# evidence 页已不在库里；对比请把 qa-dir 写到 $PWD/reel-out/
run1/at-00-0_20s.png  md5 3fff0c8a837fb8db3197326c71dab0ea   ← scale=0
run1/at-01-2_00s.png  md5 7b13e4acdf71848c6e570030357d55c2   ← scale=60
run1/at-02-4_50s.png  md5 3fff0c8a837fb8db3197326c71dab0ea   ← scale=0，与 0.2s 逐字节相同
run1 vs run2：3/3 SAME
```

三条结论都是硬的：

1. `t=0.2` 与 `t=4.5` 的 md5 **完全相同** —— 证明这一页确实没有别的随时间变化量，
   两次截帧的差异只可能来自 SMIL；
2. `t=2.0` 的 md5 不同 —— SMIL 的位移**真的被 seek 驱动了**，不是冻在 0；
3. 跑两遍 3/3 逐字节相同 —— **可复现**。

`variant-a` 整页（SMIL 滤镜 + `reelDraw` 色差）也做了同样双跑：0.62 / 2.14 / 4.22s
三个点 md5 两两相同（`6c4365b6…` / `5adc068f…` / `d91848ed…`，证据在
`evidence/variant-a-run1` 与 `-run2`）。

**为什么能成立**：SMIL 的时间轴是 `<svg>` 元素自己的一条时钟，
`pauseAnimations()` 把它停住，`setCurrentTime(t)` 把它钉到绝对时刻 ——
和 CSS 动画被 `document.getAnimations()` 接管是同一个道理。
**前提是动画必须有限次**（这里 `dur="5s" fill="freeze"`，没有 `repeatCount`）；
如果写 `repeatCount="indefinite"`，末帧就会像反例 A4 一样闪回起点。

**但 variant-a 仍然不推荐做主力**，原因是**可控性**：位移量来自噪声场，
「这次发作要错开 30px」这件事做不到，只能调 `scale` 这个总强度；
而且 `feTurbulence` 在 1280×720 上每帧全量重算，是三个方案里最贵的。
它的价值在于提供一种**不同的质感**（模拟磁带式的连续块状剪切），
以及证明了 SMIL 这条技术路线在本 skill 下是通的。

### 推荐

**主方案 `index.html`**。理由是可控性和可读性都最好：每条切片的位置、色差强度、
信号丢失都能逐个指定，发作幅度是字面量数组里一个数，改节奏就是改数组。
canvas 版（variant-b）观感几乎等价但代码量大得多、复用性差；
SVG 滤镜版（variant-a）质感独特但不可控。

## 5. 踩坑记录

### 1. 每帧改字的 DOM 读数让「同一 t 两次截帧」偶发失败（最贵的一个坑）

当时的机器验收 第一次跑就报了：

```
[FAIL] determinism: t=1.25s 两次截帧不一致（非确定性！）
```

把两张 PNG 逐字节相减，**只有 366 个字节不同，最大差值 1/255**，
位置固定在 `x:681-735, y:582-598` —— 正好是时间码读数 `T+1.25` 那 54px。

排查过程（每一步都是实测，不是猜）：

1. 单独截 `--at 1.25` 跑 5 遍 → **5/5 相同**。所以不是 `t` 的算术问题。
2. 跑完整的 `--at 0,1.25,2.5,3.75,4.999` 序列 6 遍 → **6/6 相同**。
   说明只在系统高负载时才复现。
3. 加 8 路 CPU 忙循环后跑 16 次 → `t=0` 与 `t=1.25` 各出现 2 个哈希值。
   **复现了**。
4. 先试「干净期不写 `translate(0px,0px)` 而写 `none`」（避免 `.world` 被提升成合成层）
   → `t=0` 好了，`t=1.25` 还在。
5. 再试 `-webkit-font-smoothing: antialiased`（关掉 LCD 次像素抗锯齿）
   → 还是 `t=1.25` 还在。
6. 把读数文字冻成常量再跑 → **仍然 2 个哈希值**。所以与「文字内容变化」无关。
7. 定位到方向：`.labels` 用的是 `display:flex; justify-content: space-between`，
   中间那段读数的 **x 坐标取决于左右两段中文的实测宽度**，
   而中文字宽在首次绘制时可能晚一拍才定下来 → 读数落在亚像素相位不同的位置 →
   抗锯齿覆盖率差 1/255。
8. 改成三个子元素各自 `position:absolute` 锚定整数坐标 → 仍然偶发。
9. **最终修法**：把两个会变的读数（`T+…` 与 `发作 n / 7`）和右上角状态字
   **全部画进 canvas**，DOM 里只留不动的中文说明。

```js
function setReadout(tc, bc) {
  readCtx.clearRect(0, 0, 1128, 22);          // 每帧整块重绘
  readCtx.font = "15px " + MONO;
  if ("letterSpacing" in readCtx) readCtx.letterSpacing = "1.5px";
  readCtx.textBaseline = "middle";
  readCtx.fillStyle = "#74879f";
  readCtx.textAlign = "left";  readCtx.fillText(tc, 537, 12);
  readCtx.textAlign = "right"; readCtx.fillText(bc, 1128, 12);
}
```

画布每次整块重绘，不经过 DOM 布局，也不依赖字形缓存，不受合成层栅格化时机影响。

**验收**：8 路 CPU 满载下跑 **20 次**双截帧，
`t=0 / 1.25 / 2.5 / 3.75 / 4.999` 五个采样点**各自只有 1 个哈希值**（20/20 逐字节一致）。

> 教训：当时的机器验收 的确定性检查抓到了这个坑，但**报的是「非确定性」而不是「哪一行代码」**。
> 必须自己把差异像素定位出来（`blend=all_mode=difference` + 逐字节数），
> 才能从「1/255、366 字节、某个坐标区间」倒推出「亚像素文本栅格化」这个方向。
> 如果只看 FAIL 一行就去乱改时间轴，会永远修不掉。

### 2. 第一版扫描线读起来像给标题加了个「框」

扫描线是一整块 1128×116 的矩形纹理，在深色底上左右两端收得很硬，看起来像分割线。
改成 `mask-image` 两端羽化 + 基础透明度从 0.05 降到 0.04：

```css
-webkit-mask-image: linear-gradient(to right, rgba(0,0,0,0) 0, #000 9%, #000 91%, rgba(0,0,0,0) 100%);
```

### 3. 撕裂亮线横贯画面，像分割线

第一版 `tear` 是 `left:76px; width:1128px`（整个内容宽）。改成从字身量出来的
`INK.left / INK.width`，让它只落在字形范围内 —— 它属于字形，不是画面分割线。

### 4. 发作太窄，15 格 contact sheet 只有 1 格看得出故障

第一版用三角尖包络（`a * (1-d/w)²`），`w=0.05~0.10`。
结果 sheet 采样率是 `14.5/5 = 2.9fps`，**只有第 12 格撞上了收尾大发作**，
其余 14 格看起来完全一样 —— 一个「看得出在动」的反面教材。
改成平台型包络并把 `w` 提到 0.22–0.46 后，可见发作从 1 格提到 6 格，
同时发作之间的干净静止段仍 ≥ 0.22s（多数 ≥ 0.35s），SPEC 要求的
「故障之间是干净的静止态」没有被破坏。

### 5. variant-a 的 `feDisplacementMap` 把文字揉成波浪而不是撕开

`baseFrequency="0.012 0.82"`（X 低频、Y 高频）看着对，实际是反的：
X 频率 0.012 在 1128px 宽上跑 ~13 个周期，**同一行内的位移就在变**，
于是文字被揉成连续波浪，像发虚不像故障。

正确的各向异性是 **X 极低频、Y 中频**：`baseFrequency="0.0015 0.10"`
（整幅宽才 ~1.7 个周期，一带之内位移几乎恒定；文字带内约 10 条横带），
再加 `feComponentTransfer` 把 R 通道 `type="discrete"` 分级取样成 7 档 ——
连续噪声变成离散档位，才是故障特征的那种横向块状剪切。

```xml
<feComponentTransfer in="n" result="nq">
  <feFuncR type="discrete" tableValues="0 0.167 0.333 0.5 0.667 0.833 1" />
  <feFuncG type="discrete" tableValues="0.5 0.5 0.5 0.5 0.5 0.5 0.5" />
  <feFuncA type="discrete" tableValues="1 1 1 1 1 1 1" />
</feComponentTransfer>
<!-- G 通道钉成常数 0.5：yChannelSelector=G 于是恒无纵向位移 -->
```

另外 `feTurbulence` 的 alpha 也是噪声，直接送进 `feDisplacementMap` 会让纵向
跟着乱抖；`feFuncA` 钉成 1 才干净。

### 6. variant-b 第一版在大发作时糊成一团白块

`ROW=10` + 位移上限 62px + 丢失阈值 0.86，4.22s 那一帧几乎不可读。
改成 `ROW=14` + 上限 54px + 阈值 0.88 后，行变粗、白块消失，与主方案观感接近。

### 7. 注释里写 `Math.random` / `setInterval` 会被 lint 误伤吗

不会 —— 当时的机器验收 会先剥掉 `/* */`、`<!-- -->` 和 `//` 再 lint。
但反例 A1 正是靠注释里的墙钟字样骗过了 rAF 检查，所以我把说明性注释里的
这些字样换成了中文描述，不留任何歧义。
