# 一批特效做完之后，值得单独留下来的结论

这份文档不重复各特效 README 的实现细节。它只收**跨特效复用**的东西：
方法、判据、踩过的坑，以及那些「下次一定还会遇到」的问题。

> **关于文里的特效名**：这些结论最初是从 22 个特效里归纳出来的，本库后来精简到 19 个。
> 文中提到的 `矩阵雨` / `半调网点` / `液态融合` **已不在目录里**，保留名字是为了给结论留出处
> （它们的实测数字仍然有效）；**当前有哪些特效，以 [INDEX.md](INDEX.md) 的目录为准**。

---

## 0. 一句话总纲

> **画面 = f(t)。** 不是 `f(上一帧)`，不是 `f(到达路径)`，也不是 `f(墙钟)`。

这批特效里**每一次返工**都是在把某个 `f(别的什么)` 掰回 `f(t)`。
下面所有结论都是这句话的推论或它的检验手段。

---

## 1. 验收：四道关，谁也替代不了谁

| 关卡 | 抓什么 | 抓不到什么 |
|---|---|---|
| **静态 lint** | 时间来源不唯一（`Date.now` / `setInterval` / 裸 rAF / `infinite`） | 绕过 lint 的间接累加 |
| **同 `t` 双截帧逐字节一致** | 不可复现（`Math.random()`、墙钟） | **确定性地错**的累加器 |
| **换 seek 路径同一 `t` 一致** | 真值不是 `t` 的函数（累加器 / 跨帧状态） | 与 `t` 无关但恒定的写法 |
| **人眼看 contact sheet + 首末帧** | 冻帧、露馅、主次颠倒、丑 | —— |

**第三关是本次探索最大的方法学收获**，单独展开见 §2。
**第四关永远不能省**，见 §3。

## 2. ⭐ 「可复现」不等于「是 t 的函数」

### 2.1 盲区

`capture.mjs` 每次都**按同一顺序** seek 同一批 `t`。于是纯累加器

```js
drops[i] += speed;          // ❌ 跨帧状态
```

拿到的调用次数**恒等于**它预期的次数 —— 它是**确定性地错**，不是随机地错，
**照样通过「同 `t` 两次一致」**。

### 2.2 补丁与三份独立复现

后来补上一次**单帧直取**：让浏览器「第一次 seek 就直奔 `t = duration/2`」，
与「先经过 0 和 25% 再到达同一个 `t`」比对。**归一化路径不同，纯函数必须给出同一画面。**

这条检查在**三个不同特效**上被三位不同子代理各自复现过一次：

| 特效 | 纯函数版 | 累加器版 |
|---|---|---|
| 矩阵雨 | `da0bb1898b3bcdb0` = `da0bb1898b3bcdb0` ✅ | `f6da06101c` ≠ `2f2d743778c78675` ❌ |
| 星空穿梭 | `059723e2…` = `059723e2…` ✅ | `f2dc20d0…` ≠ `9f9d6b41…` ❌ |
| 雷达扫描 | `46a9f6e0…` = `46a9f6e0…` ✅ | `b7515111…` ≠ `5f51ed87…` ❌ |

它上线后**第一次抓到真缺陷**是遮罩转场：`clip-path: path("")` 是非法值，
Chromium 整条丢弃、元素**保留上一段的 clip-path** → 画面停在旧遮罩上。

> **教训（可推广到任何「快照式」渲染系统）**：
> 同一输入的两次快照一致，只证明**可复现**；
> 要证明**输出是输入的函数**，必须改变**到达该输入的历史路径**。

## 3. ⭐ 指标本身也会骗人：三个密度指标里只有一个能用

我先后用了三个「画面有没有动」的指标，**前两个都在静默地测编码噪声**。

### 3.1 实测判决

| 指标 | 实测 | 判定 |
|---|---|---|
| `framemd5` 逐字节相同 | 把**同一张 PNG** 循环编码 15 次，解回来 **10 个不同哈希** | ❌ |
| `YMAX` 最大像素差 | 同源编码的相邻帧 `YMAX` 就能到 **48** | ❌ |
| **`YAVG` 平均像素差** | 噪声地板 **≈0.005**，真实动效 **0.5–3** | ✅ 差两个数量级 |

**根因**：x264 的码率控制逐帧改变 QP，去块滤波跟着 QP 走 ——
**输入逐字节相同 ≠ 输出逐字节相同**。

⇒ **确定性只能在页面层验（`Page.captureScreenshot` 的 PNG，无损），
不能在成片层验（MP4 解码帧）。** 对 MP4 做哈希比对没有意义。

### 3.2 最终判据

`YAVG < 0.02`（约噪声地板的 4 倍）算「这一帧没动」，统计**最长连续静止段**：
`>1.5s` FAIL / `>1.0s` WARN。八个已验收特效的数字**全部与各自 README 的时间轴吻合**
（数字滚动 0.77s ↔ 0.8s 定格、文字乱码解码 0.80s ↔ 0.85s 定格、运镜视差/矩阵雨 0.00s）。

### 3.3 它的盲区（必须知道）

`YAVG` 是**整帧平均**，会被大面积静态背景稀释：一条 2px 细线在动，`YAVG` 可能只有 0.06。
**它只能抓「整屏真的不动」，抓不到「动得太少」。** 后者只能靠人眼把 sheet 当 15 张封面看。

## 4. 时间原语：五把锤子，各有各的钉子

| 原语 | 表达式 | 用在 |
|---|---|---|
| 单段插值 | `span(t, t0, t1)` + 缓动 | 一次性的生长/位移 |
| 错峰 stagger | `span(t, t0 + i·Δ, t1 + i·Δ)` | 一排东西依次入场 |
| 事件冲击 | 字面量 `T_IMPACT` + `A·e^(−ku)·sin(wu)` | 盖章、撞击 |
| 循环相位 | `(phase0 + speed·t) % period` | 扫描、流动、雨 |
| 时间量子 | `Math.floor(t·RATE)` + `hash(i)` | 闪烁、抖动、跳字 |

### 4.1 量子频率怎么选（踩坑换来的）

**最糟的选择是帧率的整数分之一。** 霓虹灯管原本写 `RATE = 15`，
而 `15 = 30/2` —— 量子**恰好每 2 帧才变一次**，形成完美的 2:1 交替。

| | 最长静止段 | 静止占比 |
|---|---|---|
| `RATE = 15` | 0.53s | **27%** |
| `RATE = 13`（`30/13 = 2.31` 帧） | 0.40s | **15%** |

**同一份代码、只改一个数字，死帧少了 12 个百分点。** 选择次序：

1. **先大于帧率**（每帧必换值，最保险）
2. 否则取**与帧率互质**的数（不整除，图案错开）
3. **绝不要取帧率的整数分之一**（`fps/2`、`fps/3`… 会产生规则的双帧/三帧纹）

### 4.2 离散递增动画的通用约束

终端回放算密度时发现：**逐字速率 `cps` 必须大于帧率**。
若 `cps < fps`，每帧推进不到一个字，就出现「一个字都没变」的帧对 ——
**打字动画自己把自己变成冻帧**。

⇒ 任何「离散递增」的动画（逐字、逐行、逐格、逐项）都要让**每帧推进 ≥ 1 个单位**。
若为了观感必须慢，就让**别的东西**同时动（光标、进度、描边），别让整帧真的停住。

## 5. 解析 vs 覆盖：一个反复出现的分岔

凡是「拖尾 / 余辉 / 累积痕迹」，都有两条路：

| | 解析式 | 覆盖式 |
|---|---|---|
| 拖尾 | 在 `t−k·Δ` 各画一次位置 | 每帧把上一帧画布乘 0.95 |
| 余辉 | `f((ang − a) mod 2π)` | 每帧 `alpha *= 0.95` |
| 累积量 | 速度的**解析积分** | `z -= v·dt` |
| 相位 | `(φ + S(t)) mod RANGE` | `p += v·dt` |

**一律选解析式。** 覆盖式不只是「不精确」——它是**跨帧状态**，
会被 §2 的换路径检查当场抓住（雷达扫描的 `trail-accum.html` 就是这么被抓住的）。

### 5.1 「速度的积分」不是「速度乘时间」

星空穿梭给出的判据值得背下来：`z = v(t)·t` 在 `t=2.5` 给 `13000`，
真值 `6110`（**+113%**）；在 `t=3.4` 给 `0`（**跃迁那一刻星野会原地不动**）。
有加速段时必须逐段积分（`W(u) = u³ − u⁴/2`，`W(1) = 1/2`）。

## 6. 「状态」可以换成「计数」

雷达扫描没有用「已捕获」这个布尔量，而是用**累计扫过次数** `floor((Ω−aᵢ)/2π)+1 ≥ 1`。
于是「第二次扫到同一个目标」不需要任何额外状态就自然再爆闪一次。

**把状态换成计数，就把「状态机」换成了「纯函数」。** 这是本库最值得推广的一个手法。

## 7. 可见性交给几何，不要交给时间线

3D 卡片翻转的反面写法：

```js
front.opacity = span(t, 0.5, 1.85);      // ❌ 两条时间线
back.opacity  = span(t, 1.85, 3.2);      // ❌ 改一个忘了另一个
```

两个区间在 `t=1.85` 附近**两面同时半透明**；时间点稍微错开就出现**两面都不可见的空档**；
改一个忘另一个还会「角度已 180° 而背面还是透明的」。

**正解**：可见性完全交给 `backface-visibility`（**几何剔除，由累积矩阵算出来**），
`deg` 是全片唯一姿态真值，背面 `rotateY(180deg)` 是**常量补偿角**。
两条可见性判据 `cos deg > 0` / `cos deg < 0` **互为补集**，
所以「两面同现 / 同隐」在**数学上不可能**。

`deg = 90°` 的退化点（两面面积同时为 0）由两条 16px 侧棱顶上 ——
**我独立从成片量过：第 42 帧轮廓 35px，卡片没有消失。**

## 8. 名次/排序：`rankOf` 是阶跃函数，必须插值

条形竞赛的反面写法 `y = rankOf(vals[e]) * ROW_H`：名次一变，`y` **瞬间跳一整行**
（实测 **60.00px**，连升两级 **120px**）。
正解 `rankLerp` 用常量锚点 + `easeInOut` 分段插值，因 `easeInOut` 两端导数为 0，
它是**全局 C¹**，单帧位移被 `60·2ΔR/(0.48·30)` 封顶（1 级 8.33px、2 级 16.67px）。
我从成片逐帧量标签质心：**最大 4.04 px/帧**。

### 8.1 一条数学结论（不是实现问题）

> 两个实体的名次互换时，两条 y 路径**必然在某一时刻相等**。
> 交换前 A 在 B 上方、交换后 A 在 B 下方，`y_A − y_B` 连续且两端异号，
> **由介值定理必有零点。任何连续动画都躲不掉。**

⇒ 问题从「怎么避免重叠」变成「**怎么让重叠的那 1–2 帧可读**」。
解法：上升者的名字在重排中途左移一个名宽再回来（纯 `t` 函数），
交叉瞬间画面上是「**拾光 星图**」两名并排 —— 两个实体都还能被认出来。

## 9. 确定性毛边：`hash(i)`，不是 `Math.random()`

印章盖下的印面毛边：先用矢量几何画好（外圈/内细圈/五角星/两条弧字），
再用 `destination-out` 沿外圈环带**挖掉 2200 个由 `hash(i)` 决定的斑点**。
**没有任何 `Math.random()`** ⇒ 毛边逐帧稳定（不闪），且每次导出都一样。

半调网点同理：网点的清晰时刻/半径全由 `hash(块坐标)` 与解析式决定。
**矩阵雨与马赛克揭示各自论证过为什么是 `hash(块坐标)` 而不是 `hash(帧号)`**：

| | `hash(块坐标)` | `hash(帧号)` |
|---|---|---|
| 收敛性 | **可构造证明** | 只是概率（尾部必然漏块） |
| 单调性 | 只降不升 | 每帧独立抽样，清晰的块会**糊回去**（闪烁） |
| 与 fps 的关系 | 真值是 `t` 的函数 | `帧号 = floor(t·fps)`，30/60fps 下不同 |
| 掩码形态 | 成片推进 | 白噪声 → 永远撒胡椒面 |

## 10. 结束态：要「慢到可以停眼」，不要「冻住」

- **叙事型**特效必须结束在一张**完整的构图**上（印章落定、终端跑完、最终排名弹出）。
- **环境型**特效（矩阵雨、星空巡航）只需末帧处在一个**稳定的循环相位**。

**「保持结束态」≠「冻结」。** 数字滚动被打回过一次：末段 2.5s 一帧不动。
印章盖下主动偏离 SPEC 的「t≈3.0 后完全静止」，改成物理真实的「墨继续渗 + 渗前沿外扩 +
纤维继续爬」，视觉上仍是干净结束态，而 `density` 落在 `0.53s / 14%`。

> **判据是「这段静止有没有信息量」，不是「静止了几秒」。**
> 3D 卡片翻转的尾段有 39% 静止帧，但我判定不改 —— 背面是一张四行条形表，
> 画面停住是为了让人读完。这和「信息早就读完、画面还冻着」性质不同。

## 11. 性能：真正的悬崖在哪

| 写法 | 实测 | 倍数 |
|---|---|---|
| 粒子聚合：canvas | 1m31s | 1× |
| 粒子聚合：DOM + 父级 `drop-shadow` | **8m52s** | **5.8×** |
| 霓虹灯管：SVG 三层 / canvas / DOM `text-shadow` | 2m23s / 2m38s / 2m20s | 同量级 |
| 马赛克揭示：SVG 15360 个 `<rect>` 各自 `fill=url(#pattern)` | **cdp timeout(20s)** | 跑不动 |

**结论**：
- **`filter: drop-shadow` 挂在大量元素上 = 等合成器**（不是等 CPU）。
- **SVG 里「N 个元素各自引用同一个 pattern」的代价是 O(N × 贴图面积)**，不是 O(N)。
  马赛克揭示改成「1 张 1:1 image + mask 里 N 个白 rect 改 `fill-opacity`」才跑得动。
- **预计算不一定更省**：条形竞赛的帧表方案每帧 0.278ms（主方案 0.638ms），
  但**建表一次 11.74ms，是整片运行时计算量的 18 倍**，且把 fps 钉死。
  **5 秒的片子做预计算是亏的。**
- **导出墙钟被 CDP 截图 + PNG 编码（≈1.0s/帧）淹没** ——
  多个子代理独立指出「别把墙钟当绘制速度的证据」。这条自觉很重要。
- **成本常常不在你以为的那一环**（VHS失真实测）：
  主方案 canvas `drawImage` 0.10–0.57 s/帧、SVG `feTurbulence` ≈0.4 s/帧、
  **canvas 逐像素 `getImageData` ≤0.06 s/帧（最快）** ——
  **「像素级一定最慢」被推翻了**。
  更关键的是：导出总耗时由**画面多噪**主导（噪声图 PNG **1.40 s/帧** vs 平坦图 **0.54 s/帧**），
  **不由渲染循环主导**。这解释了为什么本库所有特效的导出墙钟都在同一量级。

## 12. 静默失败：最贵的 bug 不报错

| 案例 | 表现 |
|---|---|
| `clip-path: path("")` 非法 | Chromium 丢弃声明，**保留上一段的值** → 画面停在旧遮罩 |
| `var lab` 覆盖 `function lab()` | `TypeError` → 整块仪表+标题不渲染，**页面静默停在初始 SVG** |
| 颜色字符串少右括号 | 静默失效 |
| `opacity` 缓存永远命不中 | 静默失效 |
| `stroke()` 内部重设 `globalAlpha` | 12% 的暗管被画成 100% |
| `radial-gradient` 默认 `farthest-corner` | 圆盘半径只有 70.7% |
| `∫₀ᵗ`（U+2080/U+1D57） | 在 Noto Sans Mono CJK SC 里是**豆腐块** |
| `stroke-dasharray: 0 L` + `round` 线帽 | 起笔处渲染出一个 8px 亮斑 |
| 回绕淡入的 alpha 最低档是 0.28 而非 0 | 回绕瞬间星会以 0.28「爆点」 |

**共同特征**：画面**不是空白**，而是「看起来完成度还行」的半成品。
⇒ **看到「改了没反应」，先怀疑改动根本没生效**，而不是继续在同一处调参数。
⇒ 雷达扫描为此专门写了 `evidence/domcheck.mjs`（假 DOM 巡检）。

## 13. 逐帧改 DOM 文本 = 字形栅格化抖动

Chromium 在高负载下对逐帧变化的文本会产生 **1/255 抖动**，
表现为同一 `t` 两次截帧差几百字节 —— 只在系统忙时偶发，**最难查**。

**三种处理档次**：

1. **画进 canvas**（终端回放、霓虹灯管的主方案）—— 把坑从可能性里删掉，**最高档**。
2. 值没变就不写（矩阵雨）—— 缓解。
3. 冻结常量 —— 下策。

终端回放整个页面 DOM 里只有 `.stage` + `<canvas>`，
所以「每帧改 DOM 文本」的代码**根本不存在**，`verify` 的 `[NOTE]` 自然不触发。

## 14. 度量自觉：不要用被淹没的数字宣称结论

好的子代理会主动说「这个数字不可信」：

- 雷达扫描：「全量导出墙钟 index 110s / a 117s / b 97s 差异基本是 CDP 截图+编码噪声，
  **我因此没把它当 CPU 结论**，README 只给了每帧写入次数的静态对比。」
- 半调网点：「导出耗时被 CDP 截图+PNG 编码（~1.0s/帧）淹没，
  墙钟只能区分出 variant-b 更贵 —— 这是个诚实的度量说明，
  **而不是把 167s 当成"绘制很快"的证据**。」
- 霓虹灯管：变体 B 同代码两遍差 **18.6%** ⇒ 宿主噪声大于方案差异。
- 玻璃拟态：「性能那三个数字是单次测量，噪声大，**别当成可靠基准**。」

**这种自觉比数字本身更有价值。**

## 15. 一次「因节奏而非正确性」的返工

马赛克揭示：画面完全正确、`verify` 全绿、`hash(块坐标)` 的论证也成立，
**唯一的问题是主次颠倒** —— 特效叫「揭示」，而揭示只占全片 38%（我用 Sobel 边缘能量
逐帧量出揭示在 `t≈1.9s` 就到顶，之后 3 秒只有很轻的推近）。

改成揭示完成于 `t=3.30s` 后：揭示占 **66%**，`density` 从 `0.53s/17%` 变成 `0.50s/13%`，
mp4 还从 1538KB 降到 **1172KB**（慢揭示更省码率）。

> **工具查不出「重点不突出」，只有人（和它的用意）能查。**
