## 1. 效果

从**静止星野**起手（星是点，不是线），随后径向加速，星点拉成向外飞的流线，
中段速度到峰值（星轨最长），再减速、在 `T_JUMP = 3.40s` 跃迁闪白一瞬，
闪白之后换到**一片全新的星野**并稳定在**恒定高速巡航**（末帧是稳态巡航相位）。

场景内只有一套仪表：`跃迁速度 VELOCITY ×10³ u/s` 的 18 格速度表 + 阶段文案
（静止/加速/峰值/减速/跃迁/巡航）。两者都由同一个 `t` 派生（见 §3.4）。

## 2. 常见写法为什么在本 skill 里会坏

| 常见写法 | 坏在哪 | seekable 改法 |
|---|---|---|
| `z -= speed * dt; if (z <= 0) z += D;` | `z` 是**跨帧状态**。seek 到 `t=2.5` 只会推进一帧，画面等于 t≈0；同一 `t` 的答案取决于「到达它之前播了多少帧」 | `u = (phi_i + S(t)) mod RANGE`，`z = ZF - u` —— **取模回绕**，纯函数 |
| `z = z0 + speed(t) * t` | 解析、可 seek，但**数学是错的**：`speed` 不是常数，`v(t)·t` 不是位移。t=2.5 时真值 6110，`v(t)·t` = 13000，差 113% | `S(t) = ∫₀ᵗ v dτ` 的**分段闭式**（§3.1） |
| 覆盖式拖尾 `ctx.fillStyle='rgba(0,0,0,.2)'; fillRect(...)` | 依赖上一帧画布内容，seek 直接跳帧就残影错乱 | **解析式拖尾**：直接求该星在 `t, t-DT, …, t-K·DT` 的位置连线段 |
| `Math.random()` 撒星 | 每次 seek 星位都不同 | `hash(i) = frac(sin(i·127.1+311.7)·43758.5453123)`，按 `i` 取 |
| `animation: ... infinite` 做流动 | 末帧回到第 0 帧，且 seek 不可控 | 全部走 `reelDraw(t)`；本页 CSS animation 数量 = **0** |
| `transition` 做加速 | 墙钟补间，seek 不会等它跑完 | 速度由 `v(t)` 解析给出 |
| 逐帧改 DOM 文本显示读数 | 高负载下 Chromium 字形缓存 1/255 抖动（PATTERNS §6.1） | 主方案所有读数 `ctx.fillText` 画进 canvas；variant-a 用「预渲染 6 个词 + 切 opacity」，全程不写 `textContent` |

## 3. 关键技术点

### 3.1 `z(t)` 必须是速度的**解析积分**（本特效的核心证明）

速度曲线（世界深度单位 / 秒）。为了 `v(0)=v'(0)=0`（起手真的静止）且各段边界
导数为 0（加速度连续），升降速都用 smoothstep `w(u) = u²(3-2u)`：

```
v(t) = 0                                t < 0.35
     = V1 · w((t-0.35)/1.95)            0.35 ≤ t < 2.30     V1 = 5200
     = V1                               2.30 ≤ t < 2.70
     = V1 · (1 - w((t-2.70)/0.70))      2.70 ≤ t < 3.40
     = V2 · w((t-3.40)/0.70)            3.40 ≤ t < 4.10     V2 = 3800
     = V2                               t ≥ 4.10
```

积分（`W(u) = ∫₀ᵘ w = u³ - u⁴/2`，`W(1) = 1/2`；升速段用 `W`，降速段用 `u - W`）：

```
S(t) = ∫₀ᵗ v dτ
     = 0                                t < 0.35
     = V1·1.95·W(u)                     0.35 ≤ t < 2.30,  u = (t-0.35)/1.95
     = S1 + V1·(t-2.30)                 2.30 ≤ t < 2.70
     = S2 + V1·0.70·(u - W(u))          2.70 ≤ t < 3.40,  u = (t-2.70)/0.70
     = S3 + V2·0.70·W(u)                3.40 ≤ t < 4.10,  u = (t-3.40)/0.70
     = S4 + V2·(t-4.10)                 t ≥ 4.10

S1 = V1·1.95/2 = 5070    S2 = S1 + V1·0.40 = 7150
S3 = S2 + V1·0.70/2 = 8970              S4 = S3 + V2·0.70/2 = 10300
```

```js
function ss(u) { return u * u * (3 - 2 * u); }          // smoothstep
function Fs(u) { return u * u * u - 0.5 * u * u * u * u; }   // 它的原函数

function dist(t) {                                       // = S(t)
  if (t <= T0) return 0;
  if (t < T1) return V1 * W1 * Fs((t - T0) / W1);
  if (t < T2) return SA + V1 * (t - T1);
  if (t < T3) { var u = (t - T2) / W3; return SB + V1 * W3 * (u - Fs(u)); }
  if (t < T4) return SC + V2 * W4 * Fs((t - T3) / W4);
  return SD + V2 * (t - T4);
}
```

**为什么不能写 `speed(t) * t`**（当时 `evidence/integral.mjs` 第 1 节实测，脚本已不在库里）：

| t | v(t) | S(t)=∫v | v(t)·t（错） | 误差 |
|---|---|---|---|---|
| 1.0 | 1348.1 | 312.96 | 1348.15 | +1035.2 |
| 2.0 | 4868.6 | 3544.08 | 9737.28 | +6193.2 |
| 2.5 | 5200.0 | **6110.00** | **13000.00** | **+6890.0** |
| 3.4 | 0.0 | 8970.00 | 0.00 | −8970.0 |
| 4.9667 | 3800.0 | 13593.46 | 18873.46 | +5280.0 |

因为 `v` 从 0 一路涨到 5200，「瞬时速度 × 总时间」在每个时刻都严重高估位移；
而在 `t=3.4`（跃迁）`v` 恰好为 0，这个错式又给出**零位移**，星野会原地不动 ——
错得非常显眼。`S` 必须逐段积分并把分段常数（5070 / 7150 / 8970 / 10300）接上。

### 3.2 取模回绕：位置只由 `t` 决定

```js
var u = (phA[i] + D) % RANGE;      // phA 是星的固有相位；D = S(t)（跃迁后从 SC 重新计里程）
var z = ZF - u;                    // u=0 → 远平面 ZF=3200；u=RANGE → 近平面 ZN=420
var s = FOC / z;                   // 透视： screen = world * FOC / z
SX = CX + (xw - CX) * s;
SY = CY + (yw - CY) * s;
// 回绕必须看不见：alpha 分档里第 0 档是真的 0，正在淡入/淡出的星整档不画
var a = BR[i] * fi(u) * fo(u);
BUCK[i] = CI[i] * NAL + (a < 0.02 ? 0 : a < 0.44 ? 1 : a < 0.60 ? 2 : a < 0.80 ? 3 : 4);
```

- **没有 `z -= …`，没有 `if (z<=0) z+=D`。** 星在 `u` 走到 `RANGE` 时靠取模自己回到远平面。
- 回绕必须**看不见**：星在回绕瞬间位置会从近平面（画面外/很大）跳回远平面（中心附近/很小）。
  所以相位两端各有一段 alpha 斜坡 —— 淡入取相位开头 60 单位（几何位移 <1.5%，不会在正中
  掏出空洞），淡出取相位末段 14%：回绕发生在 alpha 已为 0 的地方，不会「爆点」。
- 星野在 `t=0` 是**屏幕均匀**的：横向坐标由「想要的屏幕半径 ρ0」反推
  `r_w = ρ0·z0/FOC`，而 `ρ0 = RHO·√hash` 在圆盘内面积均匀。
  （先试过「世界圆盘均匀 + 深度均匀」，边缘会因为圆盘壁露出来而变稀 —— 四角是空的。）

### 3.3 解析式拖尾（不是覆盖式）

```js
for (var k = 0; k <= K; k++) {            // K = 5, DT = 0.042s
  var tau = t - k * DT; if (tau < 0) tau = 0;
  var is2 = tau >= T3;
  var D = is2 ? (dist(tau) - SC) : dist(tau);
  var u = ((is2 ? PH2[i] : PH1[i]) + D) % RANGE;   // 同一个第 i 颗星，在 τ 时刻的相位
  ...
}
// 第 k 段 = (t-(k-1)DT) 与 (t-kDT) 两个解析位置之间的线段
```

- 因为投影是**纯径向**的（`ρ ∝ 1/z`，方向不变），K 个采样点必然共线：拖尾的**几何**
  就是一条径向直线，K 段只是给它一个从尾到头渐亮的 alpha 斜坡。所以这里不需要近似。
- 跨**回绕**（`u_k ≥ u_{k-1}`）与跨**跃迁**（epoch 变化）的段直接丢掉，否则会画出一条
  从画面边缘横穿回中心的假拖尾。
- **拖尾长度 ∝ 速度**（当时 `evidence/integral.mjs` 第 2 节，同一屏幕半径 500px 的星）：

  ```
  L = |ρ(z(t-Δ)) - ρ(z(t))| = r_w·FOC·(1/z(t-Δ) - 1/z(t)) = r_w·FOC·扫过距离/(z·zPrev)
    = 500·(1 - z/(z+扫过距离))，  扫过距离 = ∫v = v̄·Δ

  t        v(t)     v̄窗口    扫过距离   L(px)   L/v(t)
  0.0000     0.0      0.0        0.0     0.00   0.0000   ← v≡0，轨长恒为 0：点是点
  0.5000    87.6     21.1        4.4     1.17   0.0133
  1.0000  1348.1    998.2      209.6    49.68   0.0369
  1.5000  3292.5   2878.4      604.5   120.68   0.0367
  2.0000  4868.6   4611.4      968.4   168.81   0.0347
  2.5000  5200.0   5200.0     1092.0   182.49   0.0351   ← 峰值
  3.0000  3153.4   4162.4      874.1   157.55   0.0500
  3.3500    75.8    717.2      150.6    36.72   0.4844
  4.1000  3800.0   3509.3      737.0   139.74   0.0368
  4.9667  3800.0   3800.0      798.0   147.89   0.0389   ← 巡航
  ```

  加速段（1.0→2.5s）速度 ×3.9，轨长 ×3.7，`L/v` 稳定在 0.035。
  小位移极限 `L ≈ (ρ0·Δ/z)·v̄ = 0.0553·v̄`（t=0.5 实测 0.0551，吻合）；
  扫过距离大到可与 z 相比时有透视饱和（分母 `z+swept`），但 `L` 仍严格单调于 `v`。

### 3.4 单源仪表

```js
var vv = vel(t);                       // 唯一速度真值
var prog = clamp(vv / V1, 0, 1);       // 18 格表 + 数字读数由它派生
ctx.fillText((vv/1000).toFixed(2), ...);
var pi = t < T0 ? 0 : t < T1 ? 1 : t < T2 ? 2 : t < T3 ? 3 : t < T4 ? 4 : 5;   // 阶段文案
```

阶段边界（0.35/2.30/2.70/3.40/4.10）与 `v(t)`/`S(t)` 的分段边界是**同一组字面量常量**，
不存在第二套开始/结束时刻；末帧读数是 `巡航 CRUISE / 3.80`（巡航速度恒定，不是「100% 配 LOADING」）。
没有跨段的 `gbar.json`、没有手画全片进度条。

> 若以后要把多个特效 concat 成整片：本页这套**场景内**速度表会与 kit 的底栏进度条同时出现。
> 那时应把阶段信息改走 kit 的 `gbar.json` + `REEL.offset`，或者干脆去掉场景内仪表 ——
> 不要留着两套「进度」语义。

### 3.5 跃迁闪白（事件型动效）

```js
var fl = t < T3 ? span(t, T3 - 0.05, T3) : (1 - span(t, T3, T3 + 0.30));
var fa = fl * fl;                      // T3=3.40 是字面量时刻，不用「检测」
```
闪白层是覆盖全屏（含 HUD）的径向渐变白。闪白期间星野已换成 `PH2/XW2/YW2`
（另一组 hash 通道），并且跃迁后的里程从 `SC` 重新起算 —— 所以 `t=3.35`（旧星野、
几乎静止）与 `t=3.45`（新星野 + 0.69 不透明度白）必须明显不同。

## 4. 三方案对比

| | 主方案 `index.html` | variant-a `DOM 星点` | variant-b `几何隧道` |
|---|---|---|---|
| 主体 | 780 颗星，canvas 点云 + 辉光贴图 | 380 个 `<i>`，每个 1 条胶囊光条 | 16 个 14 边形环 + 14 条母线 + 154 个流动刻度 |
| 拖尾实现 | 5 段解析采样（`t-k·DT`）叠 `lighter`，尾淡头亮 | 1 个元素：长度=解析位移，`linear-gradient` 做尾淡头亮 | 每个环画 3 个解析重影（`t, t-0.013, t-0.026`） |
| 每帧绘制原语 | ~3900 线段 + 780 `drawImage` | 380 次 `style` 写（transform/width/opacity） | ~380 线段 + 48 条环 + 154 圆 |
| t=0 星野 | 780 点在位、均匀、为 0 长度 → 纯点 | 380 点（同公式，只少一半） | 隧道静止：环清晰无重影 |
| 全量导出 | **166s** | **233s** | **215s** |
| 观感 | 细腻的星流，速度线细而长，中心留出视灭点 | 更「实心」的棒状光条，DOM 辉光偏软；星少，明显更稀 | 规整的六边形隧道骨架，速度感来自环向外流 + 刻度流动；不是星空而是通道 |
| 复用性 | 高：换 `PH/XW/YW/hash` 通道即可换星野；速度曲线独立可换 | 中：DOM 数量是硬上限 | 中：几何参数（环数/边数/扭转）与观感强耦合 |
| 代价 | canvas 一次画完，元素数与绘制量解耦 | 元素数 = 星数；每帧 380 次样式重算，实测比 canvas 多 40% 时间，却只画了一半的星 | 静态母线不参与运动，画面里有一部分永不变化，密度检查要靠环的流动撑住 |

**推荐主方案。** 理由：
1. 只有它会用到「解析式拖尾」的完整形态（K 段渐变），也就是本特效要证明的那个原语；
2. canvas 让「星数」和「绘制成本」解耦 —— 780 星比 variant-a 的 380 星更密、更像星空，
   导出反而更快（166s vs 233s，同一台机、同一 `--jobs 1`，负载有波动，趋势明确）；
3. variant-a 的价值是**反例**：DOM 每条光条要 3 次样式写入，星数一上去就顶到墙。
4. variant-b 证明了同一套「取模相位 + 解析积分」可以驱动完全不同的几何（点云 / 隧道壁），
   但它的轨道母线是静态的，作为独立特效略显单调。

三份文件的 `vel()` / `dist()` / 常量完全一致（逐字复制），这是可复用的核心。

## 5. 踩坑记录

1. **星野四角是空的。** 第一版横向坐标取「世界圆盘面积均匀 + 深度均匀」，理论上
   （无限大圆柱）屏幕密度处处相等，但世界半径 1500 相对焦距 700 太小，圆柱壁在
   z≈3200 处就露出来了 —— 边缘比中心稀约 2 倍，四角明显发空。
   改成**由屏幕半径 ρ0 反推 `r_w = ρ0·z0/FOC`**后，t=0 的星野按构造成像均匀。

2. **亮星变成「硬边盘子」。** 用 `ctx.arc` + 固定 alpha 画辉光，得到的是一张等 alpha 的
   实心圆盘，在大星上非常显眼（一张 40px 的灰盘子）。改成 **load 时预渲染一张 64×64
   径向渐变辉光贴图**（3 种颜色各一张，缓存），每颗星 `drawImage` 缩放绘制 ——
   才有真正的辉光衰减，且不每帧重生成。

3. **DOM 版每帧重写 `style.background` 渐变。** 第一版在 `reelDraw` 里给 340 个元素
   每帧写 `linear-gradient(...)`，等于每帧重新解析 340 条渐变。改成 init 时写一次
   （颜色本来就是静态的），只让几何每帧变。

4. **隧道重影间隔取大了。** 第一版 `EDT=0.055`，峰值 `v=5200` 时重影相位差 286，
   而环间距只有 174 —— 重影落在另外两圈环上，画面变成「凭空多出一倍的环」，
   不像运动模糊。改成 `EDT=0.013`（相位差 ≈62，环间距的 36%），重影才贴着本环。

5. **当时的机器验收 中途被改版。** 我开工时它是 `framemd5` 逐帧哈希 + `YMAX` 两条密度线；
   00:36 再跑时已换成 `YAVG` 一条（`YAVG_TH=0.02`）。本文的验收结论以**改版后**的输出为准。
   （复核时请注意这条，别拿旧版的两行去对。）

6. **不要用 `ctx.arc` 之外的方式凑「原语数量」** —— 我一度想用 `lineCap:'round'` 的
   零长线段当星点，但那样静止时每颗星会被拖尾层多叠 5 次 alpha，亮度失控。
   现在静止段靠 `u_k < u_{k-1}` 的判据**根本不下笔**，`t=0` 的星严格只有 `drawImage` 那一层。

7. **回绕淡入/淡出算出来了却没接到画面上（最阴的一个）。** 为了把 780 颗星压成十几个
   批量 `stroke`，亮度是**分档**的（`BUCK[i]` + `ALV[档]`）。第一版的分档表是
   `ALV = [0.28, 0.46, 0.68, 0.95]` —— **最低档是 0.28 而不是 0**，而 `fi`（淡入）、`fo`（淡出）
   算完之后没有任何人去用它。后果：正在回绕的那颗星不是以 alpha=0 出现，而是以
   0.28 突然出现在中心附近 —— 就是设计里明确要避免的「爆点」。
   静态 lint、三条 determinism、肉眼扫 sheet 都**不会**报这个（一帧里只有 1–2 颗星在回绕，
   和「背景里多了一颗小星」没有区别）。
   修法：分档表补上第 0 档 `ALV = [0, 0.28, 0.46, 0.68, 0.95]`（`NAL 4→5`），
   `BUCK[i]` 由 `BR[i] * fi * fo` 每帧重新分档，绘制时整档跳过 `lv===0`。
   教训：**凡是「算出来准备用」的量，都要回头确认它真的被用到了** ——
   静默失败不只发生在 CSS 声明被丢弃，也发生在自己写的中间变量上。

## 8. 五帧对比（`--at 0.0 / 0.5 / 1.5 / 3.0 / 4.96`）
