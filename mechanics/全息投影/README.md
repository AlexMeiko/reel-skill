> 一个半透明的全息线框立方体悬浮在底座上方：一道扫描线由下往上把它「逐层扫描成影」，
> 成形之后**同一条线**继续往复扫过、带着轻微色散与量子化信号抖动，底座投出光环与光锥。
>
> 本特效要证明的核心命题：**「成形扫描」与「持续扫描」是同一条 y 轴真值的两个阶段**，
> 不是两套时间线。全文用一个可量测的负控把它钉死。

## 1. 常见写法为什么在本 skill 里会坏

| 常见写法 | 在本 skill 里的真实失效 | seekable 改法 |
|---|---|---|
| `animation: scan 2.4s linear infinite` | **它其实能过「同 t 两次截帧一致」**（`seek.js` 会 `pause()` + 设 `currentTime`，含 CSS 动画）。坏在语义：`t=duration` 时相位绕回起点，末帧 = 第 0 帧；而且 `infinite` 没法表达「成形结束后换一种扫描」 | 相位写成取模 `s(t) = (83 + 205·t) mod 610`，成形与持续共用它（见 §2） |
| 墙钟 `requestAnimationFrame` / `Date.now()` | 画面与 `t` **无关**；headless 会话只活几十毫秒，红点恒在起点，于是「确定性地错」也能过同 t 双截帧 | 只读 `window.__reelTime`，或干脆全走 `reelDraw(t)`（本方案用后者，一条 rAF 都没有） |
| `transition` 当主时间轴 | 墙钟补间，seek 不等它跑完 → 画面**滞后于 t**（反例 A5） | 一切由 `reelDraw(t)` 直接写终值 |
| 累加器 `phase += v * dt` / `drops[i]++` | 位置取决于「被 draw 了多少次」，不是 `t`；换个 seek 路径答案就变（反例 A3） | `(s0 + v*t) % H` 闭式取模 |
| `Math.random()` 每帧重掷抖动 | 不可复现，seek 无意义（反例 A2） | `hash(q)`，`q = Math.floor(t*RATE)`（§5） |
| 每帧改 `textContent` 写读数 | Chromium 字形缓存栅格化 1/255 抖动，高负载下偶发不一致（PATTERNS §6.1） | 读数画进 `<canvas>`；本方案 HUD 全是 `ctx.fillText` |
| 时间量子取 `RATE = 15`（= 30/2） | 量子恰好每 2 帧变一次，形成完美 2:1 交替，每两帧里有一帧几乎不变 → 死帧率翻倍（PATTERNS §6.6 霓虹灯管实测：`0.53s/27%` → 改 13 后 `0.40s/15%`） | 取**与帧率互质**的 17（30/17 = 1.76 帧），见 §5 |
| **成形用 `lerp(bottom, top, easeInOut(span(t,0.4,2.4)))`，持续另写 `((t*90)%780)-30`** | **本特效的核心反例**：两套时间线在 t=2.4 交接时，扫描线先「刹停」再**向下跳 40.78px**、随后速度腰斩。实测见 §3 | 成形前沿 = `clamp(y(t), 145, 555)`，持续扫描线 = `y(t)`，**同一个 y(t)** |

## 2. 关键技术点：一条 y(t)，两个相位

```js
/* ===== 唯一的扫描真值 —— 整个特效只有这一条 y 轴时间线 ===== */
var S0 = 83, V = 205, H = 610, Y_LO = 720;
var T0 = 0.40, T_FORM = 2.40;

function scanS(t) { var s = (S0 + V * t) % H; return s < 0 ? s + H : s; }  // 相位（取模，非累加）
function scanY(t) { return Y_LO - scanS(t); }                              // 扫描线 y

var Y_TOP = scanY(T_FORM);   // 145 —— 立方体顶点，不是手填的
var Y_BOT = scanY(T0);       // 555 —— 立方体底点，不是手填的

window.reelDraw = function (t) {
  var yScan = scanY(t);                                                     // 唯一的真值
  // 成形前沿：同一个 yScan，只是夹了一下；t ≥ T_FORM 钉在顶点（单调不回头）
  var formY = t >= T_FORM ? Y_TOP : Math.max(Y_TOP, Math.min(Y_BOT, yScan));
  var prog  = (Y_BOT - formY) / (Y_BOT - Y_TOP);                            // 0 → 1
  ...
  formRect.setAttribute("y", formY.toFixed(3));                             // 成形遮罩 = 同一个 formY
  sline.setAttribute("y", (yScan - 1.3).toFixed(3));                        // 扫描线   = 同一个 yScan
};
```

**统一表达式（交付口径）**

```
s(t) = (83 + 205·t) mod 610               相位，px
y(t) = 720 − s(t)                         扫描线 y，px

成形前沿   y_form(t) = clamp( y(t), 145, 555 )      ← 同一个 y(t)
持续扫描线 y_scan(t) = y(t)                         ← 同一个 y(t)

145 = y(2.40)   ← 立方体顶点由 T_FORM 反推
555 = y(0.40)   ← 立方体底点由 T0  反推
```

三个数（83 / 205 / 610）与两个时刻（0.40 / 2.40）锁死：`83 + 205×2.40 = 575 ≡ 575 (mod 610)`，
`720 − 575 = 145` 正好是立方体顶点；`83 + 205×0.40 = 165`，`720 − 165 = 555` 正好是立方体底点。
**「成形结束时扫描线正好落在立方体顶点」不是调出来的巧合，是同一个式子的必然。**

### 为什么两个相位必须是同一个函数（不是审美问题）

成形前沿与持续扫描线在 t=2.4 交接。若各写一套，交接处会出现**三个可量测的破绽**：

1. **速度断崖**。`easeInOut` 在 u=1 处导数为 0 —— 成形最后一帧只走 0.72px，而稳态是 6.83px/帧（差 9.5 倍）。肉眼看到的是「扫描线爬到顶就停住了」。
2. **位置跳变**。持续扫描另起一条式子（SPEC 草稿的 `((t*90)%780)−30`）在 t=2.4 给出 185.43，而成形前沿停在 144.65 —— **一帧内向下跳 40.78px**，方向还反了。
3. **速度腰斩**。交接之后负控跑 3.11px/帧（90px/s），只有成形期的一半。

本方案把成形写成「同一个 `y(t)` 夹一下」，所以**三个破绽一个都不存在**：
成形期与持续期的 |Δy| 恒为 205/30 = **6.83px/帧**，穿过 t=2.4 也不变。

### 唯一的取模回绕，被藏在看不见的地方

`s` 从 610 绕回 0 时 `y` 从 110 跳到 720（t = 2.5707）。它没有变成画面上的跳变，因为扫描线的
不透明度在两端各自 30px 内淡到 0：

```js
var fadeHi = reel.clamp((yScan - 110) / 30, 0, 1);   // y=110 → 0
var fadeLo = reel.clamp((720 - yScan) / 30, 0, 1);   // y=720 → 0
var vis = lineOn * Math.min(fadeHi, fadeLo);         // 回绕发生在 vis=0 处
```

立方体带是 y∈[145,555]，`fadeHi` 在 145 处已 = 1（clamp 后 1.17），`fadeLo` 在 555 处 = 1，
所以**在整个立方体范围内扫描线都是满亮**，只有跑到立方体之外才淡出。
回绕发生在 y=110→720 的一瞬间，两端 vis 都是 0 —— 画面上没有第二个跳变点。

## 4. 方案对比

| | **主方案 index.html** | variant-a | variant-b |
|---|---|---|---|
| 立方体 | SVG `<line>` ×12，等距投影顶点是字面量 | canvas，正交投影 + 绕竖直轴匀速转 θ=0.80(t−0.30) | DOM `<div>` ×12，等距投影 |
| 成形遮罩 | SVG `<clipPath>` 里一个 `<rect>` 的 y/height | **逐棱参数裁剪**（求 y=formY 交点，只画 y≥formY 的一段） | 一个 `clip-path: inset(formY 0 0 0)` |
| 扫描线 | 3 个 `<rect>`（亮线 / 辉光 / 拖尾带）每帧改 y | canvas 逐行 `fillRect`（拖带 27 行 + 辉光 17 行） | **静态 repeating 纹理**，只写 `mask-position-y = y(t)` |
| 色散 | 3 层 `<g>` + `mix-blend-mode: screen`，逐棱 `translate(dx,0)` | 3 遍描边 + `globalCompositeOperation='lighter'` | 3 层 div + `screen`，逐棱 `translateX(dx) rotate(a)` |
| 每帧写入量 | ~60 次属性写 | ~150 次 canvas 描边（36 段 × 4 遍 + 44 行填充） | ~90 次样式写（含 36 次 transform 字符串） |
| 扫描真值 | `scanY(t)` | `scanY(t)` | `scanY(t)` |
| 代价 | 中。3 个 SVG 高斯模糊滤镜每帧重新光栅化 | **最高**。每帧 36 段路径 ×4 遍 + 逐行填充，且旋转让每帧顶点都要重算 | 低。纹理零重绘；但每次改 mask-position 都要重新合成 660×720 的遮罩层 |
| 可读性 | 高（DOM 结构即几何） | 中（3D 变换 + 裁剪 + 色散混在一个循环里） | 中（CSS mask 坐标系要解释，踩坑 ⑤⑥ 都在这里） |
| 复用性 | 高（换 8 个顶点就是任意线框体） | **最高**（换顶点就是任意 3D 线框，且能真旋转） | 低（线段一多 DOM 就爆；纹理可任意复杂是它的长处） |

**推荐主方案。** 三者的 y 真值完全一致，差别只在「用什么机制把它画出来」：
主方案用「一个 SVG 遮罩 + 三个 rect」表达同一条线，写入量最小、结构最直白，且 SVG `clipPath`
只裁几何不裁像素，天然不会把背景一起裁掉。
variant-a 的观感最「3D」（能转、有前后遮挡感、色散随深度变化），但它是三者里 CPU 最高的，
而且**为了与主方案共用 145/555 这条边界，必须用正交投影** —— 透视会让投影上下边界随 θ 变化，
成形前沿就没法落在同一个真值上。variant-b 机制最省（纹理零重绘），
但可扩展性最差，而且 mask 的坐标系最容易写错。
**若要一个「会转的全息体」，选 variant-a；若要接进成片，选主方案。**

## 5. 抖动与色散：都是同一帧内由 t / y 派生

```js
var RATE = 17;                                  // 与 30fps 互质（30/17 = 1.76 帧），绝不取 30/2 = 15
var q = Math.floor(t * RATE);                   // 时间量子：t 的纯函数，无状态
var jx = (hash(q * 1.7 + 3.1) * 2 - 1) * 1.15   // 量子位移
       + Math.sin(t * 2.1) * 0.45               // 连续微摆（保证每帧都在变，不留死帧）
       + (hash(q * 5.1 + 9.7) * 2 - 1) * 6.5 * beatEnv(t);   // 节拍大抖（字面量表 BEATS）

// 色散：同一帧内由 yScan 派生 —— 越靠近扫描线越散；再乘一个量子抖动。
// 绝不逐帧累积：偏移量是 t 的纯函数，换个 seek 路径结果一样。
var hot = reel.clamp(1 - Math.abs(midY - yScan) / 95, 0, 1);
var amt = (0.45 + 2.55 * hot * hot) * (1 + 1.5 * lock) * (0.70 + 0.60 * hash(q * 2.7 + i * 1.3));
L.cy.setAttribute("transform", "translate(" + (-amt).toFixed(3) + ",0)");   // 青 左移
L.mg.setAttribute("transform", "translate(" + ( amt).toFixed(3) + ",0)");   // 品红 右移
L.co.setAttribute("transform", "translate(0,0)");                          // 原色 不动
```

- **量子频率**：`RATE = 17`，`30/17 = 1.7647…` 不是整数比，量子边界逐帧错开，不会形成规则的双帧纹。
  （对照：`RATE = 15` 时 `30/15 = 2`，量子恰好每 2 帧变一次 —— 霓虹灯管实测死帧率从 15% 涨到 27%。）
- **色散由 y 派生**：`hot` 是「该棱中点到扫描线的距离」，所以色散最强的位置永远跟着扫描线走 ——
  它承载信息（扫描前沿在哪），不是一条与内容无关的彩边。三层 `mix-blend-mode: screen` 相加，
  青 + 品红重叠处回到近白，这就是「原色」。
- **偏移量取值**：`amt ∈ [0.45, 3.0] px`（成形瞬间的核定闪光再 ×2.5）。3px 是 1280px 宽下的
  可辨但不脏的边界；超过 ~5px 线框就开始「散架」，低于 ~0.4px 在 30fps 下看不出。

## 6. 踩坑记录（都是实际撞到并修掉的）

### ① 扫描线在 t=0 就横穿底座，首帧不成壳

第一版让扫描线全程可见。`y(0) = 720 − 83 = 637`，正好横穿底座椭圆（中心 600、ry 64），
t=0 的画面里多了一条压在底座上的亮线，静态壳不干净。
**修法**：`lineOn = span(t, 0.18, 0.55)` —— 线在 t=0.18 从 y≈596（底座下沿）淡入，
到 t=0.55 全亮，此时已升到 y≈524。前 0.2s 是纯静态壳（density 仍是 0.00s）。

### ② 缓存键写错，画面变成「历史的函数」（verify 抓出来的真 bug）

```
[FAIL] determinism: 换 seek 路径后 t=2.5s 画面不同
       （真值不是 t 的函数，疑似累加器 / 跨帧状态）：9666438b4258065f vs af9b7f24dd14b748
```

把两次截帧做差：**35232 个像素差、最大差 183、bbox = x[441,878] y[145,561]** —— 正好是立方体。

根因不在 `reelDraw` 的数学，而在一行「省写入」的缓存：

```js
var o = ((L.back ? 0.42 : 0.60) + (L.back ? 0.40 : 0.55) * hot * hot) * (1 - 0.22 * beat);
if (o !== L.o) {                       // ❌ 缓存键是中间量 o，写出去的却是 o * prog
  L.glow.style.opacity = (o * prog).toFixed(3);
  ...
  L.o = o;
}
```

成形期里，**远离扫描线的那几条棱 `hot ≡ 0` → `o` 恒定** → 比较相等 → 跳过一次写入 →
那条棱的 opacity 被冻结在上一帧的 `o × prog` 上。于是同一帧的画面取决于之前 seek 过哪里。

**修法**：缓存键必须是「最终写出去的那个值」：

```js
var ov = +(o * prog).toFixed(3);       // ✅ 缓存键 = 实际写出的值，跳过写入才是幂等的
if (ov !== L.o) { ...write ov...; L.o = ov; }
```

修完复测：t=2.5 直取 vs 先经 0/1.25 到达，**差异像素 0、最大差 0**。
（教训：`if (cached !== key)` 这种优化，`key` 必须是「写出去的东西」本身；
写成「写出去的东西的一个因子」就是把跨帧状态偷偷塞回来了 —— 而且它**能过**「同 t 两次截帧」，
只有换 seek 路径才抓得到，正是 PATTERNS §8 说的那个盲区。）

### ③ variant-b：`mix-blend-mode: screen` 加在带 `opacity` 的层上 = 没混

`.layer { opacity: 0 }` 会让这一层建立**隔离的 stacking context**，子元素只在这层内部混合，
而层里除了几条棱什么都没有 → `screen` 等于普通叠加，青/品红重叠处不会回到白。
**修法**：层 opacity 常驻 1，亮度全部交给每条棱自己的 opacity（`o * prog`）。

### ④ variant-b：`mask-repeat: repeat` + `mask-size: 100% 610px` 会多出一条幽灵扫描线

周期 610px 小于元素高 720px，所以 `yScan > 610` 时会在 `yScan − 610 ≈ 90` 处**同时出现第二条线**。
**修法**：`mask-repeat: no-repeat; mask-size: 100% 1310px`（两个周期）。第二周期落在
`yScan + 610 ≥ 720`，永远在画面外。

### ⑤ variant-b：色散偏移写成 `rotate(a) translateX(dx)` 就变成「沿棱方向平移」

CSS transform 从右往左作用：`translateX(dx) rotate(a)` 才是先转后**沿屏幕 x 平移**；
写反了偏移量会被角度吃掉（竖直棱完全不动，斜棱偏移方向错）。
**修法**：`transform: translateX(<amt>px) rotate(<ang>deg)`。

### ⑥ variant-b：地面网格用百分比 mask，结果 y≈160 以上横贯全屏

`mask-image: linear-gradient(to bottom, transparent 0, #000 22%, ...)` 让网格从 22%（=158px）就出现，
看起来像 CRT 扫描线而不是地面。**修法**：改用 px 停靠点 `548px → 582px` 起，
与主方案的 horizon = 560 对齐。

### ⑦ 中文/公式换行：「610」被折到第二行

`.law` 宽 336px 装不下 19px 等宽的 `y(t) = 720 − ( 83 + 205 · t ) mod 610`。
**修法**：去掉运算符两侧空格 → `y(t) = 720 − (83 + 205t) mod 610`，宽度 400px + `white-space: nowrap`。

### 7.4 场景内仪表的自洽

HUD 四项**全部**从同一个 `yScan` 派生，画进 canvas：

```js
var formY = t >= T_FORM ? Y_TOP : Math.max(Y_TOP, Math.min(Y_BOT, yScan));  // 同一个 yScan
var prog  = (Y_BOT - formY) / (Y_BOT - Y_TOP);
var done  = t >= T_FORM;
var pct   = done ? 1 : Math.min(prog, 0.99);      // 未达成时夹到 0.99（PATTERNS §6.2）
// HUD: "y {round(yScan)} px" / "s {round(scanS(t))} / 610 mod" / "成形 {pct*100}%" / 状态文案
```

- **文案与数字同源**：`成形 100%` 与 `成形完成 HOLO-LOCK` 都由 `done` 决定，`done` 与 `prog` 到 1 是同一个 `T_FORM`。
  不存在「一个说完成、另一个说 99%」。
- **末帧到终点值**：`T_END` 用的是**字面量 `T_FORM = 2.40`**，不是 `t / REEL.duration` ——
  所以 t=5.0 的末帧读到的是 100%，不是 99%。
- **全片只有一个「开始/结束时刻」**：`T0 = 0.40`、`T_FORM = 2.40` 两个常量，仪表、遮罩、脉冲、色散核定闪光全部引用它们，没有第二组。
- **若以后 concat 成整片**：这三个场景内读数（y / s / 成形%）是**本段局部**的，
  与 kit 的底栏（`gbar.json` + `REEL.offset`）无关，不会打架；
  但若要在整片里也显示，应改走 kit 的 HUD（`REEL.hud`）而不是自己再画一套，否则会出现两套时间基准。

## 8. 一句话总结

**成形扫描和持续扫描不是两段动画，是同一条 `y(t) = 720 − (83 + 205t) mod 610` 的两个相位。**
成形前沿只是把它 `clamp` 到立方体上下边界，持续扫描线就是它本身 ——
所以交接处 |Δy| 恒为 6.83px/帧，没有停顿、没有跳变、没有换速度。
把这件事写成两套式子，`evidence/two-timelines.html` 会在 t=2.4 那一帧
先刹停 0.72px、再向下跳 40.78px、随后速度腰斩 —— 三个破绽，一测就现。
