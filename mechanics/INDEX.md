# 特效机制库（mechanics）

> ## 配色与风格：由你决定
>
> 本目录的 19 个特效是**机制演示**，每个 `index.html` 里的配色是当时为了让机制看得清而搭的一套。
> **风格与配色按题材由你自主决定** —— 觉得这套合适就沿用，想换就整套换掉，机制都不受影响。
>
> - 要借的是**机制**（怎么写才能精确 seek），直接拿去用即可。
> - 每个 `index.html` 顶部标了「硬编码了多少个颜色、属于哪一类」；
>   哪些换色时不用动、哪些会随明度/色相关系走，见 [THEMING.md](THEMING.md)。
> - 与 `SKILL.md`、`prompt/generation.md` 的「风格由内容自选」是同一条：配色定完写进 `knowledge.md`。

## 怎么用

1. 需要某种运动 → 在下面表里找机制 → 读该特效的 `index.html`。页面本身不含 `seek.js`；直接用浏览器打开只是 t=0 的静帧。要看某一秒，用 `capture.mjs --at`，产物写 `$PWD/reel-out/`。
2. 要弄清「该用哪个时间原语」→ [FINDINGS.md](FINDINGS.md) §4 五把锤子，或 [_shared/PATTERNS.md](_shared/PATTERNS.md)。
3. 不确定某个写法会不会坏 → 先看 [_shared/anti-patterns/](_shared/anti-patterns/README.md)（5 个最小反例，实测过哪些禁用写法真的会坏）。
4. 机制用上之后，配色按题材自己定 —— 合用就沿用，不合用再换。

出片走技能根目录 `SKILL.md` 的闭环：产物写 `$PWD/reel-out/`，`--jobs $(nproc)`。
各特效 `README.md` 是做库时的设计记录（会提到当时的 `variants/`、`qa/`、`--jobs 1`），**不要当出片说明书**。
结论和反面写法仍有效；需要成片时用 `tools/capture.mjs` 从 `index.html` 导到 `reel-out/`。

## 时间原语：五把锤子

| 原语 | 表达式 | 用在 |
|---|---|---|
| 单段插值 | `span(t, t0, t1)` + 缓动 | 一次性的生长/位移 |
| 错峰 stagger | `span(t, t0 + i*Δ, t1 + i*Δ)` | 一排东西依次入场 |
| 事件冲击 | 字面量 `T_IMPACT` + `A*e^(-ku)*sin(wu)` | 盖章、撞击 |
| 循环相位 | `(phase0 + speed*t) % period` | 扫描、流动、雨 |
| 时间量子 | `Math.floor(t*RATE)` + `hash(i)` | 闪烁、抖动、跳字 |

量子频率**绝不要取帧率的整数分之一**（`fps/2` 会产生规则双帧纹）；先大于帧率，否则取与帧率互质的数。
离散递增动画（逐字/逐行/逐项）必须**每帧推进 ≥1 个单位**，否则自己变成冻帧。

## 三条最容易被忽略的判据

1. **「可复现」不等于「是 t 的函数」。** 纯累加器 `x += v` 能骗过「同一 t 两次截帧一致」，
   必须**换 seek 路径**到达同一 `t` 才能抓住。详见 [FINDINGS.md](FINDINGS.md) §2。
2. **`infinite` 其实可 seek**（`seek.js` 会 pause + setCurrentTime），它坏的是**末帧语义**
   （`t=duration` 时回到第 0 帧）。禁它是为了结束态，不是因为不确定。
3. **密度指标只有 `YAVG` 能用。** `framemd5` / `YMAX` 测的是 x264 的 QP 噪声，不是画面在动。
   噪声地板 ≈0.005，真实动效 0.5–3。
