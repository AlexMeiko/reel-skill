## 1. 常见写法为什么在本 skill 里会坏

| 常见写法 | 坏在哪 | seekable 改法 |
|---|---|---|
| `y = rankOf(vals[e]) * ROW_H`（按当前值排序直接设 y） | `rankOf` 是**阶跃函数**：名次一变，y 瞬间跳一整行。实测全片最大单帧位移 **60.00 px**、帧间加速度 **60.00 px**（见 §5） | 把名次写成 **`t` 的分段连续函数** `rankLerp`，只在「重排窗口」内用 `easeInOut` 过渡 |
| `prevRank → curRank` 做 transition / 存「上一帧排名」 | seek 架构下没有「上一帧」：直接 seek 到 `t=3.0` 时 `prevRank` 是空的，画面取决于到达路径 | 锚点表是**常量**，`rankLerp(t)` 只读 `t`；不保存任何跨帧状态 |
| `el.style.top = ...` + CSS `transition: top .5s` 当主时间轴 | `transition` 是墙钟，seek 是跳帧；连续赋值还会互相打断，最终位置取决于历史 | 全部走 `reelDraw(t)`；`transition` 一次都不用 |
| `setInterval` / 无时钟 `requestAnimationFrame` 驱动重排 | 时间来源有两个；verify 的「换 seek 路径」检查会挂 | 单一时间源 `reelDraw(t)`；本片**没有任何 rAF / 定时器** |
| `Math.random()` 决定抖动/颜色 | 同一 `t` 两次截帧不一致 | 本片不需要随机；要用就走 `hash(i)` |
| 条用 CSS 动、数字用 JS 动 | 同一量两个真值来源，交叉帧会出现「标签写着 A 的数、下面却是 B 的条」 | 一次 `reelDraw(t)` 算出 `vals[]/rk[]/axisMax`，条、数值、合计、刻度全部从这一份派生 |
| X 轴每帧用 `Math.max(vals)` 当刻度 | 领先者换人时 `max` 有折点，网格会「咔」一下 | 每期一个**字面量刻度** `AX[k]`，与值用**同一套锚点时刻 + 同一 easing** 插值 → 既无折点，又恒有 `vals_i(t) ≤ axisMax(t)`（条永远不会捅出轨道） |
| 每帧 `el.textContent = ...` 改数字 | 已知高负载下 DOM 字形栅格化会出现 1/255 抖动（见 `故障文字/README.md §5.1`） | 所有**会变的数字**（数值、刻度、期别、合计、▲n）都画在 canvas 上；DOM 只放静态文字 |

## 2. `rankLerp` 的完整定义

设实体 `e ∈ {0…5}`，期 `k ∈ {0…5}`，字面量 `V[k][e]` 为第 k 期的值，`AX[k]` 为第 k 期的最大刻度。

```
排名表      R_k(e) = 第 k 期里 e 的名次（1 = 值最大；同值按实体序打破平局）
时间常量    T_HOLD = 0.28   T_V0 = 0.78   SLOT = 0.74   VAL_D = 0.26
            S_k  = T_V0 + (k-1)·SLOT         槽 k 的起点       0.78 1.52 2.26 3.00 3.74
            TV_k = S_k + VAL_D               值到达 V_k 的时刻  1.04 1.78 2.52 3.26 4.00
            TR_k = S_k + SLOT                排名落定 R_k 的时刻 1.52 2.26 3.00 3.74 4.48
            T_END = TR_5 = 4.48              唯一的「结束」字面量时刻

排名锚点    RNK_ANCH[e] = [ (0,R_0(e)), (TV_1,R_0(e)), (TR_1,R_1(e)),
                            (TV_2,R_1(e)), (TR_2,R_2(e)), … , (TR_5,R_5(e)) ]    共 11 个

rankLerp   若 t ≤ anch[0].t           → anch[0].r
           若 t ≥ anch[n-1].t         → anch[n-1].r
           否则找 i 使 anch[i].t ≤ t ≤ anch[i+1].t：
               u = easeInOut( (t - anch[i].t) / (anch[i+1].t - anch[i].t) )
               rankLerp_e(t) = anch[i].r + ( anch[i+1].r - anch[i].r ) · u

条的位置   y_e(t) = ( rankLerp_e(t) - 1 ) · ROW_H          ROW_H = 60
```

值、刻度用**同一套锚点时刻**、**同一个 `easeInOut`**：

```
值锚点   (0,0) (T_HOLD,0) (T_V0,V_0)  然后每槽 (TV_k,V_k) (TR_k,V_k)
刻度锚点 (0,12) (T_HOLD,12) (T_V0,AX_0) 然后每槽 (TV_k,AX_k) (TR_k,AX_k)
轴锚点插值规则与 rankLerp 完全相同。
```

**为什么这样写就不跳位：**

1. `easeInOut` 在两端的导数都是 0，所以每个锚点处**左右导数都等于 0** —— `rankLerp_e(t)` 不只是连续，而是**全局 C¹**（速度也连续）。
2. 于是 `y_e(t)` 是 `t` 的 C¹ 函数，单帧位移被 `|dy/dt| / fps` 封顶：
   `max|Δy| = ROW_H · 2·ΔR / (D · fps)`，`ΔR` = 该次名次变化量，`D` = 重排窗口长 0.48 s。
   - 1 名次：`60 · 2·1/(0.48·30) = 8.33 px/帧`
   - 2 名次（拾光 5→3）：`60 · 2·2/(0.48·30) = 16.67 px/帧`
   两者都 **< 半个行距（30 px）**；而阶跃写法一次就是一整行 60 px、连升两级就是 120 px。
3. `rankLerp` 只读 `t`：seek 到任意时刻、从任意路径到达，结果都一样（§6 的「换 seek 路径」检查过）。

**一个必须写下来的数学结论（我踩到的设计坑）：**

> 两个实体的名次互换时，它们的两条 y 路径**必然在某一时刻相等**。
> 证明：交换前 A 在 B 上方、交换后 A 在 B 下方，`y_A(t) − y_B(t)` 是连续函数且两端异号，
> 由介值定理必有零点。**任何连续动画都躲不掉**，这不是实现问题。
> 所以在交叉的那 1–2 帧里，上层条会完全盖住下层条。本片的处理见 §4 踩坑 5。

## 3. 时间结构（期与期之间的三段时间分配）

每个槽 `SLOT = 0.74 s` 里固定分两拍，**先改值、再重排**（SPEC 的设计）：

```
         ┌── 值插值 0.26s ──┐┌──── 排名重排 0.48s ────┐
  槽 k:  S_k              TV_k                        TR_k = S_{k+1}
         值 V_{k-1} → V_k   值冻结在 V_k，名次 R_{k-1} → R_k
```

全片节奏：

| 区间 | 内容 |
|---|---|
| 0.00 – 0.28 | **静止起手**：完整静态壳，条长为 0（t=0 可直接当封面） |
| 0.28 – 0.78 | 条长从 0 长到 V₀；刻度 12 → 36；标题数字淡入 |
| 0.78 – 4.48 | 五个槽：值 0.26 s + 重排 0.48 s，交替五次 |
| 4.48 – 4.96 | 「最终排名」chip 淡入 + 最后一次上升高亮衰减 |
| 4.96 – 5.00 | 完全静止的结束态 |

期别标签在 `TV_k` 换期 —— 与「合计」严格同一时刻，因为合计就是 `Σ vals_e(t)`（§7 有自洽抽查）。

## 4. 关键技术点

### 4.1 锚点表：一个函数同时喂条长、名次、刻度

```js
function anchorAt(anch, t, key) {          // 分段 easeInOut 插值
  var n = anch.length;
  if (t <= anch[0].t) return anch[0][key];
  if (t >= anch[n - 1].t) return anch[n - 1][key];
  for (var i = 0; i < n - 1; i++) {
    if (t <= anch[i + 1].t) {
      var a = anch[i], b = anch[i + 1];
      var u = R.easeInOut((t - a.t) / (b.t - a.t));
      return a[key] + (b[key] - a[key]) * u;
    }
  }
  return anch[n - 1][key];
}
```

`vals[e] = anchorAt(ANCH.val[e], t, "v")`、`rk[e] = anchorAt(ANCH.rnk[e], t, "r")`、
`axisMax = anchorAt(ANCH.axis, t, "v")` —— **三者在同一次 `reelDraw(t)` 里算出来**，
所以条长、右侧数值、顶部合计、X 轴刻度不可能对不上。

### 4.2 名次表的层序只算一次，DOM 与 canvas 共用

```js
var ord = [];
for (e = 0; e < NE; e++) ord.push(e);
ord.sort(function (a, b) { return rk[a] - rk[b] || a - b; });   // 名次高的在前
// DOM:    rows[ord[pi]].el.style.zIndex = NE - pi
// canvas: 数值标签按 ord 的顺序抢占 y 波段，抢到的才画
```

这是踩坑 2 的修复：**层序必须只有一个真值来源**，否则交叉帧会出现
「标签写着 54、可见的条却是 60」。

### 4.3 交叉帧的「让位」位移（`stepAside`）

```js
/* 连续路径必然相交（§2 的介值定理），相交那一两帧上层条会完全盖住下层条。
   把「正在上升」的那条的名字在重排中途左移一个名宽再回来，两条名字就不会叠在一起。 */
function stepAside(e, t) {
  var best = 0;
  for (var kk = 1; kk < NP; kk++) {
    if (!RISER[kk][e] || t < TV[kk] || t > TR[kk]) continue;
    var s = Math.sin(Math.PI * (t - TV[kk]) / (TR[kk] - TV[kk]));   // 0 → 1 → 0
    if (s > best) best = s;
  }
  return -58 * best;
}
```

名字单独一层（`#names`），位移只加在名字上 —— 条的左端永远钉在 `x = 302`，基线不会被破坏。
`sin(π·x)` 保证位移在重排窗口两端都回到 0，所以它自己不引入任何跳变。

### 4.4 显示值一律 `floor`

```js
cf.fillText(String(Math.floor(vals[e])), ...);   // 不是 Math.round
```

`round` 会让读数在真正到位前最多 1/30 s 就显示终值 —— 正是 场景内仪表自洽 点名的
「`Math.round(prog*100)` 当完成判据」。`floor` 是它的整数版「clamp 到 0.99」：
**值没到位，显示值绝不等于终值**。结束判据是字面量时刻 `T_END = 4.48`，
不是 `REEL.duration`（末帧是 `149/30 = 4.9667`，用 duration 当分母永远差 1/30 s）。

## 6. 方案对比

|  | **主方案 `index.html`** | **variant-a** | **variant-b** |
|---|---|---|---|
| 名次/值来源 | 每帧对锚点插值 | load 时展开成 151×6 帧表，运行时查表 | 同主方案 |
| 条定位 | `transform: translateY` | `transform: translateY` | `transform: translateY` |
| 额外信息 | — | — | **排名轨迹带**（粗=已发生 / 细=之后 / 强调色=当时的第 1 名）+ 时间游标 |
| 代码量 | 428 行 / 19 167 B | 456 行 / 20 641 B | 467 行 / 21 144 B |
| 每帧纯计算（150 帧） | 0.638 ms | 0.278 ms（+ 建表 **11.74 ms**） | 同主方案 + 每帧 900 条 canvas 线段 |
| 成片 | `out.mp4` 206 840 B | `variant-a.mp4` 206 840 B | `variant-b.mp4` 263 647 B |
| 与主方案的关系 | — | **逐字节相同**（md5 `2e2a19c5…`） | 同一套条 + 多一层轨迹 |
| 可读性 | 锚点表 + 3 个纯函数，最短 | 多一层「表」的间接；画面被钉死在 fps 上 | 同主方案 + 轨迹绘制 |
| 复用性 | 只改 `V` / `AX` | 改 `fps` 必须重建表；非帧中心的 `t` 要取整 | 同主方案 |

**推荐主方案。** 理由：

- `variant-a` 与主方案**逐字节等价**（16 帧抽帧 PNG 哈希 `SAME ×16`，两个 MP4 的 md5 完全一致），
  证明「预计算查表」在这个规模下不改变画面；但建表 11.74 ms 是整片运行时计算量 0.638 ms 的
  **18 倍**，5 秒片子里它反而更贵。它的价值在「同一段要反复渲染很多次」或「片子很长」时。
- `variant-b` 的轨迹带确实多给了一层信息（整段重排历史 + 谁在什么时候领先），
  代价是每帧多 900 条线段、多一个信息点、条的纵向空间被压缩（行距 60→50）。
  做「回顾 / 复盘」型内容时值得把这条带子移植回主方案。
- 单条 5 秒特效：**主方案**。

## 7. 踩坑记录

1. **名字层背景铺满全宽 → 所有条被盖住。**
   `.nm` 当时是 `width: 1280px` + `background: #f4f1ea`（`padding-right` 只推文字，不缩背景），
   而名字层 `z-index: 3` 高于条层 `z-index: 2`。
   现象：整帧只剩 6 条轨道和发白的数字，条一根都看不见。
   修：`.nm` 收到 `left: 86px; width: 200px`（86–286），背景只覆盖名字列。

2. **canvas 数值标签与 DOM 条的层序是两套规则 → 交叉帧自相矛盾。**
   标签按实体 index 倒序抢占，条的 `z-index` 却按 `round(rk*10)` 算 —— 交叉点上两个实体
   的 `round(rk*10)` 相同，DOM 用元素顺序决定上层，于是出现
   **「标签写着 54、可见的条却是 60」**。修：同一帧只算一个 `ord` 数组（§4.2），两边共用。

3. **条高 = 行距时，一次 2 名次的交换会把 3 根条糊成一整块。**
   行距 60、条高 42 时，槽 1 的中点上三根条只隔 30 px，重叠 12 px，加上名字挤在一起，
   第一版 `--at 1.28` 看起来像「楼梯状色块」。
   修：**条高 = 行距的一半（30）**，相邻两条在重排途中最多相切，不重叠。

4. **`Math.round` 让读数提前 1/30 s 到达终值。** 见 §4.4，改 `Math.floor`。

5. **名次交换的路径必然相交（设计层，非报错）。**
   见 §2 的介值定理。第一版什么都不做时，`sheet.png` 的第 9 格（t=2.7586，正好落在
   头名交叉点上，两条 y 只差 0.7 px）会显示成「少了一根条」。
   修：`stepAside`（§4.3）让上升者的名字在重排中途左移一个名宽再回来；
   同时把「上层条会盖住下层条」这个数学事实写进 README，而不是假装它不存在。

6. **审计脚本报 `Error: 找不到 ROW_H`。**
   因为页面里是 `var ROW_H = 60, BAR_H = 30, CHART_TOP = 178, …` 一行多声明，
   正则写成 `var\s+NAME\s*=` 就只匹配得到第一个。改成 `(?:var|,)\s+NAME\s*=`。
