# 时间原语手册（PATTERNS）

> 本文件是特效库的「语法」。任何 seekable 特效都可以拆成下面几种**时间原语**的组合。
> 每个原语都给出可直接抄的实现，以及它在 seek 架构下**为什么必须这么写**。
> 配套反例见 `anti-patterns/README.md`（哪些写法会坏、坏在哪）。

---

## 0. 一条铁律

> **画面 = f(t)，不是 f(上一帧)。**

所有跨帧状态（累加器、上一帧位置、粒子速度、`drops[i]++`）都是 seek 的敌人。
写代码前先问：**「如果只给我 t，我能不能算出这一帧？」**
算不出来，就说明你藏了状态。

## 1. 基础原语

### 1.1 区间归一化 `span`
```js
u = reel.span(t, t0, t1);   // clamp((t-t0)/(t1-t0), 0, 1)
```
一切插值的地基。**永远不要**手写 `(t-t0)/(t1-t0)` 而不 clamp。

### 1.2 确定性伪随机 `hash`
```js
function hash(i) { var x = Math.sin(i * 127.1 + 311.7) * 43758.5453123; return x - Math.floor(x); }
```
用途：粒子的初相、延迟、颜色抖动、故障切片偏移。
**这是 `Math.random()` 的唯一合法替代**。需要多通道就换常数：`hash(i*3+1)`、`hash(i*7.7+13.3)`。

### 1.3 时间量子 `q`
```js
var q = Math.floor(t * RATE);          // RATE=12 → 每秒换 12 次
```
用途：乱码换字、故障发作、矩阵雨换字符。
**为什么不用「每帧变」**：seek 到同一 `t` 必须得到同一画面；而且量子化后掉帧不变样
（30fps 导出的第 37 帧和第 38 帧如果在同一量子内，画面完全相同 —— 这是特性，不是 bug）。

**量子频率怎么选**：不要取 30/60Hz（与帧率同频 → 退化成逐帧噪声，看不出节拍）。
取 12Hz 时每个量子跨 2.5 帧，人眼能数出「咔咔咔」的换字感。

**分档要用「绝对剩余时间」，不要用「自身寿命百分比」**（来自特效 02 的实测）：
```js
var rem = lock_i - t;                                   // ✅ 绝对剩余时间
var lvl = rem > 1.0 ? 0 : (rem > 0.3 ? 1 : 2);
// var lvl = (t - born_i) / (lock_i - born_i);          // ❌ 各自寿命百分比
```
用绝对剩余时间，整行会出现一条**横向收敛梯度**（左真字 → 中假字 → 右噪声），
观众一眼看出「前沿在哪」；用各自寿命百分比则每个字都停在自己那一档，整行变成均匀噪声，
**前沿反而消失了**。这是个反直觉但很关键的取舍。

### 1.4 循环相位（替代累加器）
```js
var phase = (phase0 + speed * t) % period;      // ✅ 取模
// var phase += speed * dt;                     // ❌ 累加器
```
矩阵雨的列头、透视网格的流动、跑马灯都走这条。

## 2. 缓动原语

kit 只给了 `easeOut` / `easeInOut`。下面这些自己写（全是闭式函数）：

```js
function easeIn(u)      { u = reel.clamp(u,0,1); return u*u*u; }

// 过冲回弹（卡片翻转、数字落位、印章落下）
function easeOutBack(u, s) {
  u = reel.clamp(u,0,1); s = s == null ? 1.70158 : s;
  var p = u - 1;
  return 1 + (s + 1) * p*p*p + s * p*p;
}
function easeInOutBack(u, s) {
  u = reel.clamp(u,0,1); s = s == null ? 1.70158 : s;
  var c = s * 1.525;
  return u < 0.5
    ? (Math.pow(2*u, 2) * ((c+1) * 2*u - c)) / 2
    : (Math.pow(2*u-2, 2) * ((c+1) * (2*u-2) + c) + 2) / 2;
}

// 弹性（落位后余振）
function easeOutElastic(u) {
  u = reel.clamp(u,0,1);
  if (u === 0 || u === 1) return u;
  var c4 = (2 * Math.PI) / 3;
  return Math.pow(2, -10*u) * Math.sin((u*10 - 0.75) * c4) + 1;
}
```

### 衰减正弦（冲击 / 震动 / 回弹）
```js
function damped(u, A, k, w) {          // u ∈ [0,1]
  return A * Math.exp(-k * u) * Math.sin(w * u);
}
// A = 初始振幅(px/deg)，k = 衰减速度，w = 振荡角频率
// 手感：k 越大停得越快；w 越大抖得越碎；A 是「一眼看到多大动静」
// 典型：画面震动 A=6px k=9 w=52；数字落位 A=0.06 k=8 w=30（作用于 scale）
```

## 3. 结构原语

### 3.1 错峰 `stagger`
```js
// K 个元素，整体在 [T0,T1] 内完成，每个元素占 DUR 的窗口，重叠 (1-DUR)
var prog = reel.span(t, T0, T1);
for (var k = 0; k < K; k++) {
  var u = reel.span(prog, k/K * (1 - DUR), k/K * (1 - DUR) + DUR);
  ...
}
```
- `DUR = 0.3` → 明显一个接一个
- `DUR = 1.0` → 全部同时（等于不错峰）
- **错误写法**：给每个元素写一套 `animation-delay` 的 CSS keyframes。一旦要改总时长或加元素，
  所有 delay 都要手改，而且和 `reelDraw` 里算的数字会失同步。

### 3.2 事件型动效（冲击）
```js
var T_IMPACT = 1.35;                        // ✅ 字面量常量
var u = reel.span(t, T_IMPACT, T_IMPACT + 0.5);
```
**在 seek 架构里没有「碰撞检测」**：你不能「检测到落下了再开始播后续效果」，
因为 seek 会直接跳到 t=3.0。必须把事件时刻写成常量，后续全部相对它算。
所有后续效果（震动、冲击波、墨渗）**共用同一个 `T_IMPACT`**，不许出现第二个开始时刻。

### 3.3 分层视差 / 单相机
```js
var e = reel.easeInOut(reel.span(t, 0.3, 4.2));
var cam = { x: reel.lerp(0, -180, e), z: reel.lerp(0, 0.42, e) };
for (var k = 0; k < layers.length; k++) {
  var d = layers[k].depth;                                   // 0=远 1=近
  layers[k].el.style.transform =
    "translateX(" + (cam.x * (0.15 + d)) + "px) scale(" + (1 + cam.z * (0.15 + d)) + ")";
}
```
**一个相机值，所有层共用**。每层各写一套 keyframes 是失同步的根源。

### 3.4 解析式拖尾（替代覆盖式拖尾）
```js
// ❌ 覆盖式：ctx.fillStyle='rgba(0,0,0,.2)'; ctx.fillRect(...)  ← 依赖上一帧，seek 必坏
// ✅ 解析式：画出该粒子在 t、t-dt、t-2dt … 的位置
function posAt(i, t) { /* 返回 {x,y}，纯函数 */ }
for (var k = 0; k < K; k++) {
  var p = posAt(i, t - k * DT);
  ctx.globalAlpha = Math.pow(1 - k / K, 2) * 0.8;
  ctx.beginPath(); ctx.arc(p.x, p.y, r, 0, 6.2832); ctx.fill();
}
```
代价：K 倍绘制量。收益：任意 seek 都正确。**这是粒子/星空/光绘类特效的核心改写。**

### 3.5 单源同步（数字 / 进度条 / 游标）
```js
// ✅ 一次插值，算出所有派生量，再各写一次 DOM
var v = reel.lerp(0, 128, reel.easeOut(reel.span(t, 0.3, 1.9)));
elNum.textContent  = Math.round(v);
elBar.style.width  = (v / 128 * 100) + "%";
elCursor.style.left = (v / 128 * 100) + "%";
// ❌ CSS 动条 + JS 动数字：两条时间线，seek 后必然对不上
```

### 3.6 同帧只写一次
```js
// ❌ 两段区间分别赋值，后面的会盖掉前面的
if (t > 2) el.style.transform = "scale(1.1)";
if (t > 3) el.style.transform = "scale(1.0)";

// ✅ 先按 t 求出唯一最终值，再写一次
var s = t < 2 ? 1 : (t < 3 ? 1.1 : 1.0);
el.style.transform = "scale(" + s + ")";
```

## 4. 材质原语

| 原语 | 实现 | 注意 |
|---|---|---|
| 模糊 | `filter: blur(Npx)` | 参数要由 `reelDraw` 写才可动画（不要 `infinite`） |
| 阈值化 / 液态融合 | SVG `feGaussianBlur` + `feColorMatrix`（alpha 行 `0 0 0 18 -8`，阈值 8/18≈0.44） | 纯像素运算，天然无状态 |
| 通道分离 | 三层克隆 + `mix-blend-mode: screen` | 偏移量由 hash 驱动 |
| 毛边 / 噪点 | canvas 生成一次确定性纹理（`hash(x,y)`），用 `mask-image` 引用 | **生成必须在 load 时一次完成并缓存**，不能每帧重生成 |
| 网点 | canvas 逐格画点，点半径 ∝ 亮度 | 分辨率减半再放大 |
| 玻璃 | `backdrop-filter: blur()` | **headless 下是否生效必须实测**（见 `玻璃拟态/`） |
| 扫描线 | 静态 `repeating-linear-gradient` | 只改 opacity，不要动纹理 |

## 5. 特效分类学（原语 → 特效）

| 特效 | 时间原语 | 结构原语 | 材质原语 |
|---|---|---|---|
| 粒子聚合 | 错峰 + 单段插值 | 解析式拖尾 + 点云 | 发光 |
| 文字乱码解码 | **量子** + 单段插值 | 逐字错峰 | — |
| 描边自绘 | 错峰 | 单源同步 + 路径采样 | — |
| 运镜视差 | 单段插值 | **单相机** + 分层 | 空气透视（模糊+降对比） |
| 数字滚动 | 错峰 + 过冲回弹 | 单源同步 | — |
| 故障文字 | **量子** + 节拍表 | 通道分离 + 切片 | 扫描线 |
| 液态融合 | 循环相位 + 单段插值 | 轨道运动 | **阈值化** |
| 遮罩转场 | 单段插值 | 统一遮罩函数 | 噪点溶解 |
| 3D 卡片翻转 | 过冲回弹 | 角度驱动可见性 | 投影 |
| 矩阵雨 | **循环相位 + 量子** | 列结构 | 渐隐 |
| 玻璃拟态 | 循环相位 | 分层 | **模糊** |
| 印章盖下 | **事件冲击** + 衰减正弦 | 单源同步 | 确定性毛边 |

> 注：`矩阵雨` / `液态融合` 已不在本库目录里，保留在表中是因为它们的**原语组合方式**值得参考；
> 本库当前有哪些特效，以 [../INDEX.md](../INDEX.md) 的目录为准。

> 规律：**时间原语只有 5 种**（单段插值 / 错峰 / 事件冲击 / 循环相位 / 量子），
> 组合出来的特效却是无限的。学会这 5 种，任何「动效」都能拆成可 seek 的形式。

## 6. 已知的非确定性风险源（实测，务必避开）

这一节是**用返工换来的**：同一个 `t` 截两次本该逐字节相同，但下面这些写法会让它偶发不同。

### 6.1 每帧往 DOM 写变化的文本 → 字形缓存 1/255 抖动

**症状**：当时的确定性检查报 `t=1.25s 两次截帧不一致`，差异只有几百字节、`maxdelta = 1/255`、
而且**固定在同一小块像素**（就是那段会变的读数）。**只在系统高负载时复现**，空载跑十次全过。

**根因**：Chromium 对字形栅格化有缓存，每帧改 `textContent` 会让同一段文字在不同帧走不同的
栅格化路径，末位差 1 个灰阶。

**修法**：把**会变的读数**改画进 `<canvas>`（`ctx.fillText`）。静态文字留在 DOM 里没问题。
故障文字把时间码从 DOM 挪进 canvas 后，8 路 CPU 满载下 20 次双截帧、5 个采样点各只有 1 个哈希值。

> 排查链（值得照抄）：单独截帧稳定 → 高负载下复现 → 把所有会变的文字冻结成常量仍复现 →
> 把文字换成整数锚定仍复现 → 定位到「改字」这个动作本身。

### 6.2 别用 `Math.round(prog*100)` 当完成判定

`Math.round(0.996 * 100) === 100`。于是进度条还没满、数字已经显示 100% ——
「看着满了却还在跑」。**未达成时把显示量夹到 0.99**：

```js
var shown = done ? 1 : Math.min(prog, 0.99);
```

### 6.3 只改字体的「字宽」也会抖

中文字形宽度若依赖字体加载时机，两次截帧可能差零点几像素。
**修法**：等宽 CJK 字体 + 每个字固定 `1em` 单元格，让标题宽度与字体加载时机无关。

## 7. 客观质量指标：静止段长度（用 YAVG，别用别的）

成片密度检查会算**相邻帧平均像素差 `YAVG`**，再统计
**最长连续静止段**与**静止帧占比**。判据：最长静止段 > 1.5s → FAIL，> 1.0s → WARN。

### 7.1 为什么是 YAVG（我在这上面栽过，三个指标里只有它对）

我先后用过三个指标，**前两个都在静默地测编码噪声**：

| 指标 | 实测结果 | 判定 |
|---|---|---|
| `framemd5` 逐字节相同 | 把**同一张 PNG** 循环编码 15 次，解回来有 **10 个不同哈希** | ❌ 编码噪声直接淹没了「相同」 |
| `YMAX` 最大像素差 | 同源编码的相邻帧 `YMAX` 就能到 **48** | ❌ 阈值根本没法定 |
| **`YAVG` 平均像素差** | 同源编码噪声地板 **≈0.005**，真实动效 **0.5–3** | ✅ 差两个数量级 |

**根因**：x264 的码率控制会逐帧改变 QP，去块滤波又跟着 QP 走，
所以**即使输入帧逐字节相同，解码出来的帧也不相同**。
任何依赖「MP4 解码帧逐字节相等」的指标都是无效的。

### 7.2 校准结果（阈值 0.02，约噪声地板的 4 倍）

| 特效 | 最长静止段 | 静止占比 | 与设计是否吻合 |
|---|---|---|---|
| 运镜视差 | 0.00s | 0% | ✅ 全程运动 |
| 矩阵雨 | 0.00s | 0% | ✅ 全程运动 |
| 故障文字 | 0.07s | 8% | ✅ 发作之间有短促干净段 |
| 液态融合 | 0.33s | 13% | ✅ |
| 描边自绘 | 0.37s | 19% | ✅ 尾段 0.4s 定格 |
| 印章盖下 | 0.53s | 14% | ✅ |
| 数字滚动 | 0.77s | 28% | ✅ 尾段 0.8s 定格（返工后定的） |
| 文字乱码解码 | 0.80s | 23% | ✅ 尾段 0.85s 定格 |

（`矩阵雨` / `液态融合` 已不在本库，这里保留作为校准样本。）
八个已验收特效的数字**全部与它们 README 里写的时间轴对得上** —— 这说明指标是可信的。

### 7.3 它的盲区（必须知道）

`YAVG` 是**整帧平均**，会被大面积静态背景稀释：
一条 2px 细线在动、或者整屏里只有一个数字在滚，`YAVG` 可能只有 0.06。
**所以它只能抓「整屏真的不动」，抓不到「动得太少」。**
后者只能靠人眼把抽帧当封面看 —— 机器检查永远不能替代看图。
## 8. 「可复现」不等于「是 t 的函数」（双截帧的致命盲区）

这是矩阵雨子代理挖出来的、**对整个库最重要的方法学发现**。

### 8.1 盲区长什么样

当时的机器验收原本只做「同一 `t` 截两次帧，逐字节比对」。
但 `capture.mjs` 每次都**按同一顺序** seek 同一批 `t`。于是纯累加器写法：

```js
// 反面写法：跨帧状态
drops[i] += speed;                    // 每次 draw 都推进一格
```

拿到的调用次数**恒等于**它预期的次数，于是它是**确定性地错**，不是随机地错 ——
**它照样通过「同 t 两次一致」的检查。**

### 8.2 最小对照实证（矩阵雨 `evidence/`，两页只差列头算法）

| 页面 | 直接 seek 到 `t=2.5` | 先 seek 到 `1.0` 再到 `2.5` | 判定 |
|---|---|---|---|
| `rain-modulo.html` | `da0bb1898b3bcdb0` | `da0bb1898b3bcdb0` | ✅ 与路径无关 |
| `rain-accum.html` | `f6da06101ca55aca` | `2f2d743778c78675` | ❌ 与路径有关 |

顺带一个更直观的证据：同一个 `t=2.5`，累加器版在不同调用次数下给出三套答案
（`n=2` → `5.496`、`n=150`（实时播 5 秒）→ `38.298`、解析式 → `47.324`）。

### 8.3 补丁：换路径检查

后来补上一次**单帧直取**：让浏览器「第一次 seek 就直奔 `t = duration/2`」，
与 run-a 「先经过 `0` 和 `25%` 再到达同一个 `t`」比对。**归一化路径不同，纯函数必须给出同一画面。**

负控已验：`rain-accum.html` 如实报
`[FAIL] determinism: 换 seek 路径后 t=2.5s 画面不同 … 疑似累加器 / 跨帧状态`。

> 教训（可以推广到任何「快照式」渲染系统）：
> **同一输入的两次快照一致，只证明可复现；要证明「输出是输入的函数」，
> 必须改变到达该输入的历史路径。**

### 6.5 MP4 解码帧「逐字节相同」是个幻觉（x264 会逐帧变 QP）

**实测**：把**同一张 PNG** 用 `-loop 1 -t 0.5 -r 30 -c:v libx264 -pix_fmt yuv420p` 编码，
再解回 PNG —— **15 帧里有 10 个不同的哈希**。相邻解码帧的 `YMAX` 能到 **48**，
而 `YAVG` 只有 **0.0004–0.005**。

**根因**：x264 的码率控制逐帧改变 QP，去块滤波又跟着 QP 走，
所以**输入逐字节相同 ≠ 输出逐字节相同**。

**后果**：任何「拿 MP4 解码帧做逐字节比较」的指标都是无效的（我第一版密度指标就栽在这里，
它其实一直在测编码噪声，却报告「0% 静止」）。判「画面有没有动」只能用 **`YAVG`**，见 §7。

> 推论：**确定性只能在页面层验，不能在成片层验。**
> 同 t 双截帧比对的是 `Page.captureScreenshot` 出来的 PNG（无损），
> 那是可信的；对 MP4 做哈希比对则没有意义。

### 6.6 打字速度低于帧率，会自己制造冻帧

终端回放子代理算密度时发现的：**逐字速率 `cps` 必须大于帧率**。
若 `cps < fps`，每帧推进不到一个字，就会出现「这一帧和上一帧一个字都没变」的帧对 ——
**打字动画自己把自己变成冻帧**。本片取 `cps = 34 > 30fps`，保证每帧至少多一个字。

推而广之：**任何「离散递增」的动画**（逐字、逐行、逐格、逐项）都要让
「每帧推进量 ≥ 1 个离散单位」，否则必然产生重复帧。
如果为了观感必须慢，那就让**别的东西**同时动（光标、进度、描边），别让整帧真的停住。

**⚠️ 补充（霓虹灯管实测换来的）**：时间量子频率**最糟的选择是帧率的整数分之一**。
霓虹灯管原本写 `RATE = 15`，而 `15 = 30/2` —— 于是量子**恰好每 2 帧才变一次**，
形成完美的 2:1 交替，每两帧里有一帧与前一帧几乎完全相同。
实测：`RATE = 15` → `最长静止段 0.53s / 静止占比 27%`；
改成 `RATE = 13`（`30/13 = 2.31` 帧，**不是整数比**）→ `0.40s / 15%`。
**同一份代码、只改一个数字，死帧少了 12 个百分点。**

所以选量子频率的次序是：**① 先大于帧率**（每帧必换值，最保险）；
**② 否则取与帧率互质的数**（不整除，图案错开）；
**③ 绝不要取帧率的整数分之一**（`fps/2`、`fps/3`… 会产生规则的双帧/三帧纹）。
