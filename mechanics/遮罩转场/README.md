## 1. 时间轴：全片唯一一张表

```
LEAD = 0.40   SEG = 0.70   NSEG = 6   T_END = LEAD + SEG*NSEG = 4.60   DUR = 5.00
```

| 段 | 区间 | 转场 | 基场景 → 目标场景 |
|---|---|---|---|
| — | 0.00 – 0.40 | 静止起手：**完整的 A 场景** | A |
| 1 | 0.40 – 1.10 | 圆形扩散 | A → B |
| 2 | 1.10 – 1.80 | 纵向百叶窗 | B → A |
| 3 | 1.80 – 2.50 | 斜向擦除 | A → B |
| 4 | 2.50 – 3.20 | 棋盘格 | B → A |
| 5 | 3.20 – 3.90 | 噪点溶解 | A → B |
| 6 | 3.90 – 4.60 | 径向时钟扫 | B → **C** |
| — | 4.60 – 5.00 | 定格：**完整的 C（场景 B 的结束态）** | C |

`seg = clamp(floor((t-LEAD)/SEG), 0, 5)`；`p = clamp((t - (LEAD+seg*SEG))/SEG, 0, 1)`；
`pe = shape(p)`，`shape(u) = u − 0.20·sin(2πu)/(2π)`（导数 ∈ [0.8, 1.2]，段内不是匀速，但全程都在动）。

## 2. 核心证明：一个签名，六种实现

### 2.1 签名

```js
// 六个遮罩算子对外完全是同一个签名。p 是**唯一的**进度量（= 全片的 pe）。
mask(kind, p) -> { clip }                       // 几何类：交给 clip-path
              | { mask, size, pos }              // 位图/渐变类：交给 mask-image
// p = 0 → 面积覆盖率 0%（只看见基场景）
// p = 1 → 面积覆盖率 100%（只看见目标场景）
```

调用处只有一行，六种几何没有任何分支以外的时间线：

```js
applyMask(document.getElementById(role.top), MASKS[seg].fn(pe));
```

### 2.2 六种 `mask(p)` 表达式（要求的那张表）

| # | 名称 | `mask(p)` 返回什么 | 具体表达式 | 介质 |
|---|---|---|---|---|
| 1 | 圆形扩散 | `clip` | `circle(1010·p px at 470px 330px)` | clip-path |
| 2 | 纵向百叶窗 | `clip` | `path()` × 12 条，条 k 宽 `w_k = S · clamp((p − 0.34·d_k)/0.66, 0, 1)`，`S = 1280/12`，`d_k = |k−5.5|/5.5` | clip-path |
| 3 | 斜向擦除 | `clip` | `polygon(-900px 0px, Xpx 0px, (X−300)px 720px, -900px 720px)`，`X = -300 + 1580·p` | clip-path |
| 4 | 棋盘格 | `clip` | `path()` × 144 格（16×9，每格 80×80）；格 i 可见 ⟺ `p > 0.44·((dx+dy)/2) + 0.46·((r+c)%2) + 0.08·hash(i)` | clip-path |
| 5 | 噪点溶解 | `mask` + `size` + `pos` | `url(噪点图集)`，切片 `j = round(p·24)`，`mask-size: 1280·(8−4p) px auto`，`mask-position: −j·160·(8−4p) px 0` | mask-image |
| 6 | 径向时钟扫 | `mask` | `conic-gradient(from 0deg at 640px 360px, #000 0deg, #000 360p deg, rgba(0,0,0,0) (360p+1.6)deg 360deg)`；`p ≥ 1` 时退化为 `#000 0deg, #000 360deg` | mask-image |

### 2.3 覆盖率曲线（`#selftest` 实测，采样 64×36）

| 算子 | p=0.00 | p=0.25 | p=0.50 | p=0.75 | p=1.00 |
|---|---|---|---|---|---|
| circle | 0.0% | 21.6% | 70.6% | 93.4% | **100.0%** |
| blinds | 0.0% | 15.6% | 50.0% | 84.4% | **100.0%** |
| wipe | 0.0% | 3.7% | 38.3% | 75.0% | **100.0%** |
| checker | 0.0% | 17.4% | 48.6% | 75.7% | **100.0%** |
| dissolve | 0.0% | 25.0% | 49.2% | 75.1% | **100.0%** |
| sweep | 0.0% | 25.0% | 50.0% | 75.0% | **100.0%** |

六条曲线都**单调**地从 0% 走到 100%，所以「同一个签名」不是嘴上说的：p 的语义在六种实现里逐点可比。
这张表是回归测试——它当场抓出过两个 bug（见 §6.4）。

### 2.4 没有第二条时间线

- 全片只有一个进度量 `pe`：遮罩几何、底部仪表条、仪表读数、柔光透明度，都是它的函数。
- 没有任何 CSS `@keyframes` / WAAPI / SMIL —— 当时的机器验收 的 lint 项 `无 CSS animation` 通过。
- 没有 `transition`（SPEC 明令禁止用它做转场）。
- 段边界的切换不是「另一条时间线」，而是 `seg = floor(...)` 这个纯函数的分段取值。
- 仪表用的 `T_END = 4.60` 是**字面量**，不是 `REEL.duration`（§7.6 第 2 条）。

## 3. 三套配色、三个场景层，以及一个必须说明的奇偶修正

- **场景 A「校样」**：`#f2eee3` 底 / `#fffdf6` 卡 / `#1b2027` 字 / 强调 `#a8400f`
- **场景 B「夜墨」**：`#0d151e` 底 / `#16222f` 卡 / `#eaf1f8` 字 / 强调 `#ffb347`
- **场景 C「付印版」**：`#e8a92f` 底 / `#fdf6e6` 卡 / `#221a0b` 字 / 强调 `#a8400f`

A 与 B 是**同一张信息图**（六张卡片目录 + 标题 + 底部仪表）的两套配色；C 是 B 的**结束态**：
同一张图、同一套内容，底色换成 B 家族里的暖强调色，六张卡全部打上完成标记，右上角出現「揭示完成 · 6 / 6」。

**为什么要 C（对 SPEC 的一处偏离，必须记录）**：
SPEC 写的是「A、B 两种配色的同一张信息图」。但六段转场从 A 出发、每段翻转一次场景，
**6 是偶数，所以必然回到 A**；要让末帧落在 B，就必须让其中一段的两端不是 A/B 互换。
我选择让第 6 段揭示 **B 的结束态 C**，而不是：
（a）让某一段原地不动（等于少一个转场）；
（b）把末帧停在 A（违反「末帧必须是场景 B 的完整结束态」）。

第一版我让 C 沿用 B 的深色，结果第 6 段（径向时钟扫）扫过去**画面几乎没变化**——
末帧的对错看不出来，转场本身也白做了。改成琥珀底之后，深墨 → 琥珀的明暗差让整段扫掠一目了然（见 §6.5）。

**为什么基/目标交替**：每段的起点必须正好是上一段的终点，否则段与段之间会出现「回闪」。
按 A→B→A→B→A→B→C 排列，`ROLES = [[A,B],[B,A],[A,B],[B,A],[A,B],[B,C]]`，
边界处 `p=1` 与下一段 `p=0` 给出**同一幅画面**。这不是推论，是量出来的（§5.3）。

## 4. 确定性

| 检查 | 结果 |
|---|---|
| 同一 t 两次独立截帧逐字节一致（5 个采样点） | ✅ 当时的机器验收 PASS |
| 采样帧互不相同（5/5 唯一） | ✅ PASS |
| **换 seek 路径**：先经 0/25% 到达 t=2.5 vs 直接到达 t=2.5 | ✅ 逐字节一致 |
| 静止起手 12 帧（t=0 … 0.367） | ✅ 12 张静帧 sha256 完全相同 |
| 噪点来源 | `hash(i) = frac(sin(i·127.1 + 311.7)·43758.5453123)`，verlet 无 `Math.random()` |
| 每帧变化的读数 | **全部画进 `<canvas>`**，DOM 文本从不改写（`textContent=` 出现 0 次） |

当时的机器验收 的 lint 仍报 `有 4 处每帧改 DOM 文本`（NOTE 级）：
那是 3 个场景层的 `style.opacity/zIndex` 与仪表的 `style.width`——都是**样式**写入，不是文本节点改写。
真正的文本节点（标题、卡片名、六段中文标签）全程是字面量，一个字符都没换过。

## 5. 客观证据

### 5.1 密度

```
[PASS] density: 相邻帧完全相同 1/149 对（1%）        # 阈值 ≤18% 合格
[PASS] density: 相邻帧全画面无变化 8/149 帧（5%）
```

### 5.2 帧间差剖面（量「有没有回闪」）

用 `tblend=difference` 在 160×90 灰度上量相邻帧的平均绝对差：

```
全片 149 个相邻帧差:  中位 8.11   均值 11.42   最大 47.43
静止起手 (帧 0-11)    最大 0.017     ← 完全静止
定格收尾 (帧 138-149) 最大 0.0001    ← 完全静止（帧 137→138 的 2.87 是进入定格那一步）
最大帧差 t=3.43~3.60  约 44~47      ← 噪点溶解段，一半像素每帧翻转，应当最大
```

**六个段边界处的帧差全都 ≤ 相邻普通帧的帧差**（例如 t=1.100 边界帧差 0.146，
而 t=1.133 是 3.835；t=2.500 是 1.587，t=2.533 是 3.611）。
没有一处出现「回闪」型尖峰 —— 交替基/目标的结构是对的。

> 另一个反直觉的观察：MP4 里静止段的相邻帧在 `framemd5` 下并不完全相同（1/149 对相同），
> 但**同一批 t 用 `--at` 直接截帧是 12/12 字节相同**。也就是说这点差异来自导出管线本身
> （合成器落定 / 编码器），不是页面的跨帧状态；量级 0.017/255，肉眼不可见。已在 `evidence/` 留证。

### 5.3 能力探针（`evidence/`）

| 探针 | 结论 |
|---|---|
| `clip-path: path()` 多子路径 | 可用。12 条竖条、144 格棋盘都是**一个** `path()` 字符串 |
| `clip-path: polygon()` 表达 12 条互不相连的竖条 | 靠反向绕数能出形状，但语义脆弱；**改用 `path()`** |
| `clip-path: path()` 576 子路径 | 2.56 ms/帧（含强制 layout），144 格约 0.65 ms/帧 |
| `mask-image: conic-gradient(...)` | 可用，硬边有锯齿；加 1.6° 软边过渡 |
| 噪点图集 + `mask-size`/`mask-position` | 可用。`mask-repeat: repeat-y` 让「纵向重复同一张切片」，于是 `k`（源像素→屏幕像素）可以自由变化做「粗→细」 |
| `feTurbulence` 能不能 seek | **能**。同一 t 两次独立加载截帧 sha256 相同 |
| `feTurbulence` 阈值方向 | 与直觉相反：阈值 t 越大露得**越少**；有效段只有 t ∈ [0.30, 0.72]（见 §6.6） |

## 6. 踩过的坑（每条都带原始报错 / 原始数值）

### 6.1 `path("")` 是非法值 → 元素保留上一段的 clip-path

第一版棋盘格在 `p=0` 时 `d` 是空数组，返回 `path("")`。当时的机器验收 报：

```
[FAIL] determinism: 换 seek 路径后 t=2.5s 画面不同（真值不是 t 的函数，疑似累加器 / 跨帧状态）：
       9931b71a27fbb129 vs fa597aa1f528c533
```

`t=2.5` 正是棋盘格段的 `p=0` 起点。根因用 `evidence/probe7-clip-path-validity.html` 量出来：

| 写法 | 金色（=完全没被裁剪）占比 |
|---|---|
| `clip-path: circle(0px at 200px 150px)` | 0.0% ← 合法 |
| `clip-path: path("")` | **100.0%** ← **非法，声明被整条丢弃** |
| `clip-path: path("M0 0Z")` | 0.0% ← 合法 |
| `clip-path: polygon(-20px -20px,…)` | 0.0% ← 合法 |
| 先 `circle(80px)` 再 `path("")` | **28.0%** ← 旧值 `circle(80px)` **被保留**（圆面积占比理论值 27.9%） |

所以错误是「确定性地错」：先经过圆形扩散段时，元素上留着圆形的 clip，
直接 seek 到 `t=2.5` 时元素上什么都没有——两者自然不同。
修法是空路径必须写成合法的零面积值 `path("M0 0Z")`。

**教训**：CSS 非法值是**静默丢弃**的（AGENTS.md 说的「最贵的 bug 是不报错的 bug」）。
凡是「算出来可能为空」的 CSS 值，都要有一个合法的空值兜底。

### 6.2 场景内仪表被场景层整片盖住

`.hud` 只写了 `position:absolute`，没有 `z-index`。三个场景层被逐帧写了 `z-index: 1/2/3`，
`z-index:auto` 的仪表在它们**下面**——成片里仪表整块消失（t=0 的静帧上只有空白底）。
修：`.hud { z-index: 10 }`。

### 6.3 末帧 12 点方向有一道贯穿到圆心的暗缝

径向时钟扫的软边写成 `#000 0deg, #000 (360p−1.6)deg, transparent (360p+1.6)deg 360deg`。
`p=1` 时最后一段透明停在 360° 之前，于是 12 点方向上留了一条不到 2° 的透明扇区，
在末帧上就是一道从顶边直到圆心的暗竖线（`t=4.97` 静帧可见）。
修：`p` 接近 1 时整个换成不透明渐变 `#000 0deg, #000 360deg`。

### 6.4 百叶窗在 `p=1` 只覆盖 56%

第一版把每条竖条宽度定死成 0.56 倍节距，于是 `p=1` 时画面永久是条纹，
覆盖率只有 50%（实测）——**每段转场都揭示不完全**。
这条是 `#selftest` 的覆盖率表直接抓出来的（`blinds … 1.00→50.0%`），
肉眼在 15 格里很难发现。修：条宽 `w_k = S·u`，`p=1` 时等于节距，覆盖率回到 100%。

### 6.5 第 6 段 B→C 同色时整段转场看不见

见 §3。第一版 C 沿用 B 的深色，`t=4.25` 的静帧是整个画面一片深色，
看不出任何扫掠边界。这不是「效果弱」，是这一段**没有信息**。改配色解决。

### 6.6 `feTurbulence` 的阈值方向是反的，而且有效段很窄

`evidence/probe6-turbulence-calibration.html` 实测
（`baseFrequency .09 / numOctaves 2 / seed 11 / slope 40 / color-interpolation-filters:sRGB`）：

```
intercept  −12.0 → 99.8%   −15.2 → 94.3%   −18.4 → 69.2%
           −21.6 → 23.6%   −24.8 →  3.7%   −28.0 →  0.2%
```

第一版按「intercept 越负露得越少」的直觉写，得到的是**倒过来**的曲线；
而且 alpha 分布很窄，用 `intercept ∈ [−12, −28]` 之外的区间会瞬间从 100% 跳到 0%。
修：把 `p → t` 做成 6 段线性反查表（`variant-b.html` 里的 `TURB`），保证这一段也严格 0% → 100%。

## 8. 场景内仪表自洽

底部仪表 = 六段刻度 + 当前段高亮 + `READY/REVEALING/DONE` + `0k/06` + `p x.xx`。

- **同源**：五者全部由同一个 `seg` 和同一个 `pe` 派生，没有第二个进度变量。
- **末帧到终点值**：`T_END = LEAD + SEG*NSEG = 4.60` 是字面量。末帧 `t = 149/30 = 4.9667 ≥ 4.60`
  → `DONE`、`06/06`、`p 1.00`、六段刻度全满。**没有用 `t / REEL.duration`**。
- **一个特效里只有一个开始/结束时刻**：`T_END` 在全文件只出现一次，其余地方都引用它。
- **没有跨帧状态**：当时的机器验收 的换 seek 路径检查通过。

> **concat 注意**：这些仪表目前是**画在场景内的**（HUD 是 `.stage` 的一部分，随特效一起被合成）。
> 若以后把多个特效拼成整片，应改走 kit 的 `gbar.json` + `REEL.offset`，否则会和 kit 的底栏打架。

## 9. 三方案对比与推荐

| 维度 | **主方案** `index.html` | `variant-a` 画布合成 | `variant-b` SVG 原生 |
|---|---|---|---|
| 遮罩机制 | CSS `clip-path` + `mask-image` | `drawImage` + `globalCompositeOperation='destination-in'` | `<clipPath>` / `<mask>` / `<pattern>` / `feTurbulence` |
| 几何类怎么写 | 返回 `circle()` / `path()` / `polygon()` 字符串 | `arc()` / `fillRect()` / `Path2D` 直接画 | 改 `<circle r>` / `<rect width>` / `<polygon points>` / `<path d>` |
| 棋盘格 | `path()` × 144 子路径 | 144 次 `fillRect` | 两张反相 `<pattern>` 各被一个扩散圆裁 |
| 噪点溶解 | 确定性图集 → `mask-image`，`mask-size` 插值做粗→细 | 320×180 阈值场 `ImageData`，`drawImage` 源矩形缩放做粗→细 | `feTurbulence` 硬阈值，反查表驱动 `intercept` |
| 每帧写什么 | 3 个场景层的遮罩属性 + 仪表 | 2 次全画面合成 + 1 次 `putImageData` | DOM 属性（`r`/`x`/`width`/`points`/`d`/`intercept`） |
| 同 t 双截帧一致 | ✅ | ✅（本机实测） | ✅（本机实测；`feTurbulence` 也是） |
| 可读性 / 加第 7 种 | **最好**：`mask(p)` 就是返回一个 CSS 字符串，改一处即可 | 最差：遮罩语义埋在命令式绘制里 | 中：语义清楚但属性散在多个 `<defs>` |
| 导出开销 | **最省**：遮罩交给合成器，逐像素噪声几乎免费 | 最贵：每帧两遍全画面合成 + 逐像素循环 | 中：`feTurbulence` 每帧重算 |
| 表达能力 | 弱：`clip-path` 只能表达几何，像素级要靠位图 mask | **最强**：逐像素、混合模式、发光、位移都能做 | 强：可导出矢量，能进非 HTML 管线（打印/PDF） |

### 推荐：主方案

1. `mask(p)` 是**纯函数返回字符串**，六种实现的差异一眼可读、可 diff、可单测（`#selftest` 就是给它写的回归）；
2. 不需要每帧重画画布，导出最快；
3. 浏览器把遮罩光栅化交给合成器，噪点溶解这种逐像素效果基本免费（图集方案 10–17 ms/帧，其中大部分还是 `getBoundingClientRect()` 强制 layout 的量测开销）。

两个对照方案的独有价值，保留下来备用：

- **`variant-a`（画布）**：要做「溶解 + 发光 + 位移」的复合转场，或者要读回像素做反馈，走这条线。
- **`variant-b`（SVG）**：要输出矢量、要进印刷/PDF 管线，或者转场素材本身是 SVG 时，走这条线；
  它的 `feTurbulence` 已被证明可 seek（两次独立加载字节一致），可以放心用。

**具体数值参考**（本机，`--jobs 1`）：`clip-path: path()` 576 子路径 2.56 ms/帧、144 子路径约 0.65 ms/帧；
图集 `mask-size` + `mask-position` 每帧改写 10–17 ms/帧（含强制 layout）；`feTurbulence` 改 `intercept` 的属性写入 0.06 ms/帧。
单片 150 帧导出约 1–2 分钟。
